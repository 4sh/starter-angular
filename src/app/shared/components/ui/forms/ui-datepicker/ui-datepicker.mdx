# ui-datepicker

Sélecteur de **date / mois / année** (et d'**heure** optionnelle) headless. Un champ
déclencheur [`ui-input`](?path=/docs/components-ui-forms-ui-input--docs) en lecture seule ouvre
un calendrier stylé (tokens `form.*` / `actions.*`) dans un overlay Angular CDK — ou rendu
**inline**. Sélection `single` / `multiple` / `range`, vues à tiroir (jour → mois → année),
modes `MonthPicker` / `YearPicker`, plusieurs mois côte à côte, navigation mensuelle, focus
roving et support clavier complet (motif WAI-ARIA date picker).
`p-datepicker`.

Câblé en `ControlValueAccessor` (Signal Forms `[formField]`, `[(ngModel)]` ou `[formControl]`) sur
[`BaseFormField`](?path=/docs/components-ui-forms-ui-input--docs) : `label`, `helperText`/`errorText`,
`level`, la validation et les états `disabled`/`readonly` sont partagés avec les autres champs.

**Valeur : `Date` ou string ISO, selon `valueType` (obligatoire, sans défaut).** L'input
`valueType: 'date' | 'iso'` est **requis** : pas de valeur implicite, pour forcer le choix
explicite plutôt qu'un défaut silencieux qui ne correspondrait pas au type réel du modèle. `writeValue`
accepte toujours `Date` **ou** string ISO `"yyyy-MM-dd"` (`"yyyy-MM-ddTHH:mm"` avec
`showTime`/`timeOnly`), auto-détecté — peu importe ce que l'app a sous la main. Ce qui est
**émis** (`valueChange`, `dateSelect`, donc ce qui atterrit dans le `FormControl`) suit
strictement `valueType`, jamais un mélange silencieux des deux formes :

- **`'date'`** — la valeur reste un `Date` de bout en bout, normalisé à minuit quand
  aucune heure n'est affichée (`!showTime && !timeOnly`). Pensé pour un DTO round-trippé par
  `class-transformer` (`@Type(() => Date)`) : le formulaire manipule directement le `Date` du DTO,
  sans conversion à faire côté app — la sérialisation vers le JSON du backend reste la
  responsabilité de `class-transformer`, pas du champ.
- **`'iso'`** — la valeur est une string `"yyyy-MM-dd"` (`string[]` en `multiple`/`range`). Pour
  un champ qui lit/écrit directement contre un `LocalDate` backend, sans DTO/`class-transformer`
  entre les deux (ex. un filtre de recherche). Toujours construite à partir des composants locaux
  du `Date` (`getFullYear()/getMonth()/getDate()`), jamais `date.toISOString()` (qui bascule en
  UTC et peut décaler le jour selon le fuseau local).

`Date` reste de toute façon la représentation interne de tout le calcul de calendrier — seule la
frontière `writeValue`/`commit` convertit, dans un sens ou dans l'autre selon `valueType`.

## Sélection : single / multiple / range

`selectionMode` définit la quantité sélectionnée. La valeur du modèle est un `Date`/string ISO
(selon `valueType`) en `single`, un tableau en `multiple` (bascule au clic, le panneau reste
ouvert) et un tableau `[début, fin]` en `range` (1er clic = début, 2ᵉ = fin, surbrillance de
l'intervalle).

<Canvas of={DatepickerStories.Range} />

## Vues & modes (jour → mois → année)

Un clic sur le **titre** de l'entête remonte d'un niveau : jour → sélection de mois → sélection
d'année. L'input `view` fixe la granularité de base : `date` (défaut), `month`
(**MonthPicker**) ou `year` (**YearPicker**). En mode mois/année, le clic sélectionne directement
un mois / une année.

<Canvas of={DatepickerStories.YearPicker} />

## Plusieurs mois

`numberOfMonths` affiche N panneaux mois côte à côte, séparés par un filet, avec les titres de
mois alignés en face des flèches ← → (aux extrémités). Le changement de vue à tiroir reste
réservé au mode mono-mois.

<Canvas of={DatepickerStories.TwoMonths} />

## Ouverture (placement)

Le panneau s'ouvre sous le champ et **se retourne automatiquement au-dessus** quand la place
manque en bas (CDK Overlay). `autoFlip="false"` verrouille l'ouverture vers le bas.

<Canvas of={DatepickerStories.SmartPosition} />

## Date & heure

`showTime` ajoute une ligne horaire sous forme de **steppers verticaux** (chevrons ↑/↓ autour de
chaque unité HH : MM — pattern ARIA `spinbutton`, pilotables aux flèches clavier) ;
`hourFormat="12"` ajoute un sélecteur AM/PM. `timeOnly` masque le calendrier. Quand `showTime` est
actif, le panneau **reste ouvert** après le choix d'un jour (pour régler l'heure) même si `closeOnSelect`.

<Canvas of={DatepickerStories.Time12h} />
<Canvas of={DatepickerStories.StepperOnlyTime} />

## Contraintes de sélection

`minDate` / `maxDate` bornent la plage ; `disabledDays` (0 = dimanche … 6 = samedi) et
`disabledDates` (dates ponctuelles) neutralisent des cellules. `showButtonBar` ajoute les actions
« Aujourd'hui » / « Effacer ».

`minDate`, `maxDate` et chaque entrée de `disabledDates` acceptent indifféremment un `Date` **ou**
une string ISO `"yyyy-MM-dd"` (les deux formes sont mixables dans `disabledDates`) — pratique
quand les bornes viennent déjà d'un backend au même format que la valeur. Une string malformée
dégrade silencieusement en « pas de contrainte » plutôt que de lever une erreur.

## Saisie manuelle (`allowInput`)

Par défaut le champ est en lecture seule : la date se choisit uniquement dans le panneau.
Activez `allowInput` pour autoriser la **frappe au clavier** dans le champ (mode `single`
uniquement). Le texte est parsé au **blur** et sur **Entrée** ; une saisie invalide revient
à la dernière valeur affichée. `↓` ouvre le panneau et entre dans la grille.

Quand `allowInput` est actif (et sans `dateFormat` custom), la valeur s'affiche au **format
numérique** de la locale (ex. `08/07/2026`) pour un aller-retour fiable avec le parser.

Les séparateurs **"/" s'insèrent automatiquement pendant la frappe**, dès qu'un segment (jour,
mois) est complet — même principe qu'un champ de date d'expiration de carte bancaire (`0812…` →
`08/12…`). Le segment année reste volontairement libre (pas de "/" forcé après 2 ou 4 chiffres) :
la validation stricte a lieu au parsing (blur/Entrée), pas dans ce masque cosmétique. Ce
comportement partage son moteur avec [`ui-input-mask`](?path=/docs/components-ui-forms-ui-input-mask--docs)
(`mask-engine.ts`) et se désactive automatiquement dès qu'un `parseDate` custom est fourni (un
format non numérique rendrait l'auto-slash faux).

> **L'ordre des champs suit la locale résolue** (`locale` ou, à défaut, `LOCALE_ID`). En
> `fr-FR` c'est **jj/mm/aaaa** ; en `en-US` c'est **mm/dd/yyyy** — l'auto-formatage suit le même
> ordre. Si `LOCALE_ID` n'est pas configuré, Angular tombe sur `en-US` : passez `locale="fr-FR"`
> (ou configurez `LOCALE_ID`) pour saisir en JJ/MM/AAAA. Le **placeholder est dérivé
> automatiquement** de cet ordre quand il n'est pas fourni, pour ne jamais afficher un format
> trompeur.

Fournissez `parseDate` `(value: string) => Date | null` pour un parsing sur mesure (symétrique
de `dateFormat`). Ces deux hooks travaillent en `Date` (affichage/saisie libre uniquement) — ils
ne sont jamais round-trippés à travers la CVA, donc pas concernés par le contrat ISO.

## Templates

Deux points d'extension via `<ng-template>` projetés, résolus par `contentChild` :

- **`#date`** — cellule de jour personnalisée. Contexte : `$implicit` = descripteur du jour
  (`{ day, month, year, otherMonth, today, selected, disabled, rangeStart, rangeEnd, inRange }`)
  et `selected` (booléen). Idéal pour des pastilles d'évènements, week-ends colorés, etc.
- **`#buttonbar`** — barre de boutons personnalisée. Contexte : `todayCallback` et `clearCallback`
  (fonctions à câbler sur `(click)`).

<Canvas of={DatepickerStories.DateTemplate} />
<Canvas of={DatepickerStories.CustomButtonBar} />

```html
<!-- Cellule de jour personnalisée -->
<ui-datepicker [(ngModel)]="date" valueType="date">
  <ng-template #date let-d let-selected="selected">
    <span>{{ d.day }}</span>
    @if (hasEvent(d)) { <span class="dot"></span> }
  </ng-template>
</ui-datepicker>

<!-- Barre de boutons personnalisée -->
<ui-datepicker [(ngModel)]="range" valueType="date" selectionMode="range" showButtonBar>
  <ng-template #buttonbar let-todayCallback="todayCallback" let-clearCallback="clearCallback">
    <ui-button size="small" label="Aujourd'hui" (buttonClick)="todayCallback($event)" />
    <ui-button size="small" level="error" icon="xmark" iconOnly ariaLabel="Effacer" (buttonClick)="clearCallback($event)" />
  </ng-template>
</ui-datepicker>
```

## Formulaires

Le composant est un `ControlValueAccessor` : il se branche sans code additionnel aux
**Signal Forms** (`@angular/forms/signals`, directive `[formField]`, stables depuis Angular 22)
via l'interop CVA native, ainsi qu'aux formulaires template-driven (`[(ngModel)]`) et réactifs
(`[formControl]`).

<Canvas of={DatepickerStories.SignalForms} />

```html
<!-- Signal Forms, DTO class-transformer (birth: Date) -->
<ui-datepicker [formField]="birth" valueType="date" label="Date de naissance" />

<!-- Reactive forms, DTO class-transformer (form.controls.birth: FormControl<Date | null>) -->
<ui-datepicker formControlName="birth" valueType="date" label="Date de naissance" [maxDate]="today" required />

<!-- Reactive forms, valeur ISO directe (form.controls.birth: FormControl<string | null>) -->
<ui-datepicker formControlName="birth" valueType="iso" label="Date de naissance" required />

<!-- Date + heure, ngModel -->
<ui-datepicker [(ngModel)]="appointment" valueType="date" label="Rendez-vous" showTime hourFormat="12" showButtonBar />

<!-- Inline (pas d'overlay) -->
<ui-datepicker [(ngModel)]="date" valueType="date" inline />
```

> **Périmètre / choix** : le champ déclencheur est en **lecture seule** (choix par le calendrier ;
> pas de saisie/parsing texte libre). Le tiroir de vues (jour → mois → année) et le focus roving
> clavier sont actifs en **mono-mois** ; en multi-mois les entêtes sont fixes avec flèches aux
> extrémités. Les états interactifs (hover/focus/pressed) sont des **pseudo-classes CSS** pilotées
> par les tokens, pas des props. Personnalisation via `panelStyleClass`, `#date`, `#buttonbar`.
