configuration sections of each component.

## Principle: 3 levels, one local variable per component

`_ui-config.scss` (exposed via <code>@use 'utils'</code>) declares constants at 3 scopes,
from widest to narrowest:

```
GLOBAL UI  ──►  CATEGORY  ──►  COMPONENT (local variable)
(all)           (forms /
                 actions /
                 informative)
```

- Constants are grouped by **scope**: some are **global** (shared across several
  component families / concepts common to the whole interface), others belong to a
  **category** (forms, actions, informative).
- Each component then consumes the constants it needs in its own SCSS configuration
  (local variables, maps, mixins, etc.), which lets you adjust one component without
  affecting the others.

```scss
// Example in ui-radio.scss: the shared value arrives via a LOCAL variable:
$focus-ring-width: utils.$form-focus-ring-width; // ← replace here to adjust THIS component
```

## Summary: per-component configuration

Each component's **local** variables (including those that point to `ui-config` —
per-component adjustment points) are documented in the **"Theming"** section of the
component's doc. That table is **generated** from the `.scss` by `npm run docs:config`:
each variable's role comes from its `///` comment, the binding and the chain to
`ui-config` are inferred, and the displayed value is **measured** in the active
theme, brand and viewport. Rebinding a variable in a project therefore requires no
doc update.

## How to override

  <thead>

      <td style={{ padding: 8 }}>Edit the global value in <code>_ui-config.scss</code>. Every component re-<code>@use</code>s this file, they follow.</td>
    </tr>
    <tr style={{ borderBottom: '1px solid rgba(128,128,128,.15)' }}>
      <td style={{ padding: 8 }}><strong>One category</strong> (e.g. larger form controls)</td>
      <td style={{ padding: 8 }}>Edit the `$form-*` (or `$action-*` / `$avatar-*`) variable in <code>_ui-config.scss</code>.</td>
    </tr>
    <tr style={{ borderBottom: '1px solid rgba(128,128,128,.15)' }}>
      <td style={{ padding: 8 }}><strong>A single component</strong> (e.g. a thicker ring on radio only)</td>
      <td style={{ padding: 8 }}>Replace the local variable's value at the top of the component's <code>.scss</code>.</td>
    </tr>
  </tbody>
</table>

> Two levers, that's it. Components do <code>@use 'utils'</code> (which exposes
> `ui-config`) and read each value from a **local** variable; editing `_ui-config.scss`
> therefore ripples everywhere, and replacing the local variable only affects that component.

## The `control-transition()` mixin

Applies the shared transition recipe to a list of properties (duration + easing taken
from `ui-config`), in one declaration:

```scss
@use 'utils';

.ui-checkbox-box {
  @include utils.control-transition(background-color, border-color, box-shadow);
}
// → transition: background-color 80ms ease-in-out, border-color 80ms ease-in-out, box-shadow 80ms ease-in-out;
```

Changing the duration/curve for every component = editing `$control-transition-duration` /
`$control-transition-easing` in `ui-config`.

For **enter/exit animations and state transitions** (accordion,
tooltip, overlays…), see the dedicated **motion system**: the `utils.motion-transition()`
mixin, the `utils.motion-reduce` guard, the `ui-motion-*` presets and the `[uiMotion]`
directive, documented in **Foundations → Motion** (timing in the `$motion-*` group above).

## Governance: when to create a shared constant

- A value used by **≥ 2 components** → promote it into `ui-config` (**category**
  level if specific to a `forms`/`actions`/`informative` family, **global** otherwise),
  and add it to the matching group page above.
- A value used by a **single** component → it stays **local** to its `.scss` (documented
  in its doc's "Theming" section).
- `ui-config` carries **token choices** (structure). Themeable colors remain runtime
  **design tokens**: **never** a color here.
