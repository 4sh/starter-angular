# Package npm — `@4sh/ui-kit`

Les composants de ce Design System sont publiés sous forme d'**un seul package
npm**, consommable par n'importe quelle application Angular.

```bash
npm install @4sh/ui-kit
```

Les dépendances sont en `peerDependencies` (`@angular/core`, `@angular/common`,
`@angular/forms`, `@angular/router`, `@angular/cdk`,
`@angular/platform-browser`, `rxjs`) : c'est la version déjà installée dans
votre application qui est utilisée.

Package sur npmjs : <a href="https://www.npmjs.com/package/@4sh/ui-kit" target="_blank" rel="noopener noreferrer">npmjs.com/package/@4sh/ui-kit</a>

---

## Import à la carte

Chaque composant a son propre *entry point*. Vous n'importez que ce dont vous
avez besoin, et le tree-shaking retire le reste de votre bundle :

```ts
import { UiButton } from '@4sh/ui-kit/ui-button';
import { UiIcon } from '@4sh/ui-kit/ui-icon';
```

<div className="sb-callout">

**Pas de risque d'oubli d'installation.** `@4sh/ui-kit` est un **package unique**
avec des *secondary entry points* — pas une collection de packages séparés. Tous
les entry points sont présents dès `npm install`, et les dépendances entre eux
se résolvent automatiquement : importer `UiDatepicker` tire tout ce dont il a
besoin (son socle de formulaire, ses icônes…) sans que vous ayez quoi que ce
soit à déclarer.

## Configuration requise par deux composants

Certaines données ne peuvent pas être connues du kit : elles sont **injectées**
par l'application.

```ts
// app.config.ts
import { brandFromSubdomain, provideUiKitBrand } from '@4sh/ui-kit/theming';
import { provideUiImageAssets } from '@4sh/ui-kit/ui-image';
import assetsMap from './assets/assets-map.json';

providers: [
  provideUiKitBrand(brandFromSubdomain(subdomain)),  // marque active
  provideUiImageAssets(assetsMap),                   // assets locaux de ui-image
]
```

Les deux sont optionnels : sans eux, la marque vaut `brand1`, et `ui-image`
n'affiche que ses images distantes (`src`).

---

Exemple — n'utiliser **que** le date picker, sans tirer le reste du kit dans
votre bundle :

```ts
import { UiDatepicker } from '@4sh/ui-kit/ui-datepicker';

@Component({
  selector: 'app-booking',
  imports: [UiDatepicker],
  template: `<ui-datepicker label="Date" valueType="date" [(ngModel)]="date" />`,
})
export class Booking { date = signal<Date | null>(null); }
```

## Charger la feuille de styles du kit

Les composants sont **headless** : aucune couleur, taille ni espacement codé en
dur. Le package **livre** la feuille correspondante, à charger une fois :

```jsonc
// angular.json
"styles": [
  "node_modules/@4sh/ui-kit/styles.css",
  "src/styles/main.scss"
]
```

Elle contient les design tokens (3 marques × clair/sombre × responsive), la
couche de base, les classes typographiques et les presets d'animation.
**Sans elle, les composants s'affichent sans style.**

Les `@font-face` n'y sont pas : les tokens *nomment* les familles
(`--fontfamily-base`), chaque projet livre ses polices.

Les sources SCSS sont aussi livrées (`@4sh/ui-kit/styles`) : `@use 'utils'`
donne accès aux mêmes fonctions, mixins et constantes partagées pour écrire vos
propres composants.

## `@4sh/ui-kit/forms` — construire son propre champ

Cet entry point contient l'infrastructure partagée par tous les champs du kit.
**Inutile de l'importer pour utiliser un champ existant** — `UiInput`,
`UiSelect`, `UiDatepicker` et les autres l'embarquent déjà. Il sert quand vous
créez **votre propre champ** en réutilisant les conventions du Design System.

| Export | Rôle |
|---|---|
| `BaseControlValueAccessor<T>` | Implémente `ControlValueAccessor` et miroite l'état du `NgControl` dans des signals (`touched`, `dirty`, `controlInvalid`, `controlErrors`, `showError`). Rend le champ compatible d'un coup avec `[(ngModel)]`, les Reactive Forms **et** les Signal Forms. |
| `BaseFieldControl<T>` | Contrôle « nu », sans habillage : inputs communs (`ariaLabel`, `inputId`, `name`, `required`, `disabled`, `readonly`, `invalid`, `tabindex`), `id` accessibles auto-générés, `modelValue`, états dérivés `isDisabled` / `isInvalid`. Socle de `ui-checkbox`, `ui-toggle`, `ui-slider`, `ui-radio`, `ui-nudger`. |
| `BaseFormField<T>` | Étend le précédent avec le chrome « boîte » : `label`, `helperText`, `errorText`, `size`, `level`, plus `effectiveLevel` / `displayMessage` / `displayValue`. Socle de `ui-input`, `ui-select`, `ui-datepicker`, `ui-textarea`. |
| `dropdownOverlayPositions()` | Ancrage CDK d'un panneau déroulant (sous le champ, retourné au-dessus si nécessaire). |
| `maskEngine` | Moteur de masque de saisie partagé (`ui-input-mask`, `ui-datepicker`). |

```ts
import { Component, forwardRef } from '@angular/core';
import { NG_VALUE_ACCESSOR } from '@angular/forms';
import { BaseFormField } from '@4sh/ui-kit/forms';

@Component({
  selector: 'app-my-field',
  templateUrl: './my-field.html',
  providers: [
    { provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(() => MyField), multi: true },
  ],
})
export class MyField extends BaseFormField<string> {
  // `writeValue` est fourni par défaut (écrit dans `modelValue`).
  // Appelez `emitChange(value)` à la saisie, `emitTouch()` au blur.
}
```

Votre champ hérite alors gratuitement de la gestion d'état de formulaire, des
`id`/`aria-describedby` accessibles, et du contrat visuel commun
(`label`/`helperText`/`errorText`/`size`/`level`).
