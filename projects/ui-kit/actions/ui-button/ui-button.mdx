## Variants

Beyond `level` (color), `variant` drives the appearance. `outlined` and `ghost`
compose with the chosen `level`: each pair has **its own token set**
(`--actions-<level><variant>-*`, e.g. `--actions-successoutlined-surface-hover`),
under the same contract as the `filled` set — 5 states × `content` / `surface` / `stroke`.

      <td>solid background</td>
      <td>solid background, darkens</td>

      <td>tinted at every state</td>

`outlined` and `ghost` therefore only differ by the border: it's the token that
carries the transparency (`ghost`'s `stroke-default` = `transparent`), not the CSS.
The `low` level is deliberately a notch more subtle than the others (text and
border one shade lighter).

## Button on a colored background (`onColor`)

The sets above are computed for the **page background**. Sitting on a banner, a
tinted card or an image, the button no longer has enough contrast — and `level`
can't know that:

<Canvas of={ButtonStories.OnColorOmitted} />

`onColor` declares the **background's brightness** — the only thing the caller
reliably knows — and the button pins its chrome accordingly. This is a
**third, orthogonal axis**: it combines with any `level` and any `variant`.

```html
<ui-button label="Discover" variant="outlined" onColor="dark" />   <!-- dark/saturated banner -->
<ui-button label="Discover" variant="outlined" onColor="light" />  <!-- light banner -->
```

A single principle is enough to infer everything: **`onColor` pins the surface's
polarity, and the content follows its own surface.**

    <tr>

      <td>opaque <strong>white</strong> pill, label in the <code>level</code>'s light tone</td>

    <tr>

Two properties worth knowing:

- `level` **survives** in `filled`: a white "Remove" pill stays red,
  "Confirm" stays green. In `outlined`/`ghost` the background already carries the
  color, so those sets are level-independent there.
- These sets are **theme-insensitive**: a purple banner is purple in light
  as well as dark, so `onColor` must not switch with `data-theme`. It's the
  only token family in the DS whose `modeLight` and `modeDark` values are
  deliberately identical.

### Which polarity to choose

The criterion is the background's brightness, not its hue. The two polarities
**partition the palette**: every shade falls under one or the other.

<table className="doc-table">
  <thead>
    <tr>
      <th>Background the button sits on</th>
      <th>Polarity</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>primary.500</code>+, <code>red.600</code>+, <code>green.700</code>+, <code>orange.700</code>+, <code>grey.500</code>+</td>
      <td><code>onColor="dark"</code></td>
    </tr>
    <tr>
      <td>anything lighter (including <code>success</code> / <code>warning</code> by default, at <code>{'*.500'}</code>)</td>
      <td><code>onColor="light"</code></td>
    </tr>
    <tr>
      <td><code>{'*.50'}</code> → <code>{'*.200'}</code></td>
      <td>none: the default rendering already works</td>
    </tr>
  </tbody>
</table>

> Trap worth knowing: the default surfaces of `success` (`green.500`) and
> `warning` (`orange.500`) are **light** — a success banner expects
> `onColor="light"`, not `dark`. White only reaches 2.5:1 there.

> Exactly one background in the palette escapes both polarities: brand 3's
> `secondary.900` (olive, 4.18:1 in white and 4.24:1 in dark). On a
> mid-luminance background like that one, a scrim or a different background is
> needed — no token can fix it.

## Link mode

When a button must **navigate** (internal route or URL), set `href` or
`routerLink`: the host then renders a **real `<a>`** styled as a button. The
anchor's native behavior is preserved (Cmd/Ctrl+click, middle-click, "open /
copy link"), unlike navigation triggered in JS from a `(click)`.

> Rule: pick the element by **semantics** (navigate ⇒ `<a>`, act ⇒
> `<button>`), not by appearance. For an **inline** link within text, prefer
> [`ui-link`](?path=/docs/components-ui-actions-ui-link--docs).

```html
<ui-button label="View the page" href="/pricing" icon="arrow-right" iconPos="right" />
<ui-button label="My profile" [routerLink]="['/profile']" />
<ui-button label="External site" href="https://angular.dev" target="_blank" />
```
