# ui-context-menu

Headless **contextual** menu: a right-click (or any other `triggerEvent`) on
the `target` element — or anywhere with `global` — opens a menu **positioned
at the pointer** in a CDK overlay (automatic flip at the viewport edges).

The panel **is an embedded [`ui-menu`](?path=/docs/components-ui-navigation-ui-menu--docs)**:
same declarative `UiMenuItem[]` model (nested submenus,
`command`, `routerLink` / `url`), same keyboard navigation, same
`navigation.*` tokens and same `overlay-panel` shell — at **compact
density (`size="small"`) by default**, the right density for a contextual action menu.

## API

<ArgTypes of={ContextMenuStories} />

Public methods: `show(event)` (opens at the pointer), `hide()`, `toggle(event)` —
for manual wiring with no `target`. Outputs: `opened` / `closed` and
`itemClick` (`{ originalEvent, item }`, the menu closes after activation).

The item model is **exactly** the same as `ui-menu`: see the
[`UiMenuItem` table](?path=/docs/components-ui-navigation-ui-menu--docs#uimenuitem).

## Basic

The menu attaches to an element via `target` (template reference variable)
and activates on **right-click** — the native event is intercepted (`preventDefault`)
and the panel opens at the pointer's coordinates. A click (or right-click)
elsewhere closes it; a right-click **inside the target** repositions the menu.

The menu is **anchored to the document, not the screen**: on scroll, it scrolls with
the content (like a DOM element) and stays exactly where it was opened —
flyout panels stay attached to their parent item.

```html
<div #zone>Right-click here</div>
<ui-context-menu [target]="zone" [items]="items" ariaLabel="Actions" />
```

## Submenus

Submenus are defined by **nesting items** in a parent item's
`items` property. They open as **cascading side panels**
(flyout): hover or click on the parent (`›` chevron), `→` opens and moves focus
to the first item, `←` closes and returns focus to the parent, automatic flip
at the viewport edges. Hovering another entry at the same level closes
the sibling panel that was open.

> This is the `submenus="flyout"` mode (the context menu's default). Pass
> `submenus="inline"` to get `ui-menu`'s sections / accordions instead.

## Global

`global` attaches the context menu to the **entire document**: right-clicking
anywhere opens it at the pointer (and another right-click repositions it).
Only one global menu at a time per page — it's a replacement for the native menu.

## Template

The `#item` template receives the **model item** as a parameter (`$implicit`) and
customizes the menuitem's content (the interactive element stays managed by
the component: keyboard and a11y guaranteed). `#submenuheader` is also passed through.

<Canvas of={ContextMenuStories.Template} />

## Command

The function invoked when an item is clicked is defined via `command`
(`{ originalEvent, item }`); the menu closes after activation.

<Canvas of={ContextMenuStories.Command} />

## Router

Items navigate via `routerLink` (`RouterLink` anchor), programmatic routing
in a `command` (`router.navigate(...)`), or an external `url`
(automatic secure `rel` with `target="_blank"`).

## Theming

The visual rendering (panel, items, densities, tokens) is entirely carried by
`ui-menu`: see its
[Theming](?path=/docs/components-ui-navigation-ui-menu--docs#configuration-scss) section
and the shared
[`$overlay-panel-*`](?path=/docs/components-configuration-global-ui--docs) group.
The local file only defines the overlay envelope (capping to the viewport).
