# ui-menu

Headless **navigation / commands** menu, static or **popup**, driven by a
declarative `items` model (`UiMenuItem[]`): headed groups, separators,
**collapsible submenus**, commands (`command`), router links (`routerLink`)
and external URLs (`url`).

## API

<ArgTypes of={MenuStories} />

Public methods (`popup` mode): `toggle(event)`, `show(event)`, `hide(focusTrigger?)`.
Outputs: `opened` / `closed` (popup) and `itemClick` (`{ originalEvent, item }`).

## Groups & model-driven selection

Items are grouped by the `items` property (header + flat separator between
sections). Here, checkboxes and radios are **derived from the model**: the
`command` toggles the state, and the item's icon is recomputed from that same state.

<Canvas of={MenuStories.Group} />

> Two group renderings via the `submenus` input: `inline` (sections / accordions
> below, the default) or `flyout` (cascading side panels — the mode
> used by [`ui-context-menu`](?path=/docs/components-ui-navigation-ui-context-menu--docs):
> hover/click or `→`/`←` on keyboard, parents `aria-haspopup` + `aria-expanded`).

## Collapsible submenus (`toggleable`)

**Nested** groups are collapsible by default. `toggleable` forces the
behavior per item: here the **root** group "Files" is rendered collapsible,
and the nested group "Shared" is **frozen open** (`toggleable: false`).
The collapse is animated by the motion system (grid-rows technique, like
the accordion), cut off by `[motion]="false"` / `prefers-reduced-motion`.

<Canvas of={MenuStories.Toggleable} />

## Popup

`popup` + the `toggle(event)` method: the panel opens in a **CDK overlay**
anchored below the triggering element (automatic flip above when there's
not enough room — `autoFlip`), with the `slide-down` motion preset. Closes on
outside click, on `Escape` (focus returned to the trigger) and after activating an item.

```html
<ui-button label="Options" (buttonClick)="menu.toggle($event)"
  [buttonProps]="{ 'aria-haspopup': 'menu', 'aria-controls': menu.uid }" />
<ui-menu #menu popup [items]="items" ariaLabel="Options" />
```

`#item` customizes the **content** of each menuitem (context `$implicit` =
the model item), `#submenuheader` customizes group headers; the `#start` / `#end`
slots frame the list.

## Controlled (`expandedKeys`)

`expandedKeys` defines which collapsible groups are open: an object whose **key
is the item's `id`** and value a boolean. The property is **two-way
bindable** (`[(expandedKeys)]`). With no `id`, an internal positional key is
generated — stable as long as the `items` array doesn't change, but give it an `id`
as soon as you control the state from the outside.

## Accessibility

<table className="doc-table">
  <thead>
    <tr><th>Point</th><th>Implementation</th></tr>
  </thead>
  <tbody>
    <tr><td>Roles</td><td>`role="menu"` → `role="menuitem"` on **real** `<a>` / `<button>` (never a clickable `div`); sections `role="group"` + `aria-labelledby`, separators `role="separator"`.</td></tr>
    <tr><td>Keyboard</td><td>WAI-ARIA menu pattern: **single tab stop** (roving tabindex), `↑`/`↓` wraps around, `Home`/`End`, `Enter`/`Space` activate, `→`/`←` open/close a collapsible group, `Escape` closes the popup.</td></tr>
    <tr><td>Submenus</td><td>Toggles `aria-expanded` + `aria-controls`; collapsed content is `inert` (invisible to keyboard and screen readers).</td></tr>
    <tr><td>Focus</td><td>`:focus-visible` distinct from hover (`--global-border-focus` ring, since the `navigation` family has no `focused` state). Popup opens → focus on the first item; closes → focus back to the trigger.</td></tr>
    <tr><td>Disabled</td><td>Native `disabled` on `<button>` (a disabled link entry falls back to a disabled `<button>`), `-disabled` tokens, skipped by keyboard navigation.</td></tr>
    <tr><td>Accessible name</td><td>`ariaLabel` / `ariaLabelledBy` on the list; `ariaLabel` per item if needed.</td></tr>
  </tbody>
</table>
