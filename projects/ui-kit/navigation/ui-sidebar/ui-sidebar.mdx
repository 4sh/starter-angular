# ui-sidebar

Application sidebar:

- **Static** (default): the bar lives in the flow and **pushes the content**. Collapsible into
  an **icon rail** (`collapsed`, two-way). With `openOnHover`, a collapsed rail **temporarily
  floats** open on hover / focus, without shifting the content.
- **Overlay**: the bar **floats** above the content as an offcanvas with an optional
  `backdrop`, driven by the two-way `visible` model — **focus trap** + restoration
  (`@angular/cdk/a11y`), `aria-modal`, **scroll lock**, `Escape` and outside click.

## With a menu

Full application chrome: workspace switcher in the header (`#header`), grouped
navigation via `ui-sidebar-menu`, user card in the footer (`#footer`). The trigger collapses
the bar into an icon rail — labels, section headers and badges hidden.

The `#header` / `#footer` templates receive the **resolved collapsed state** in their context
(`let-collapsed="collapsed"`), to show only icons in rail mode:

```html
<ng-template #header let-collapsed="collapsed">
  <ui-icon name="layer-group" size="lg" />
  @if (!collapsed) { <strong>App</strong> }
</ng-template>
```

## Responsive

Below `breakpoint` (here `1024px`, aligned with the design system's `$breakpoint-*` scale), the
bar becomes an offcanvas with a backdrop; above it, it stays an icon rail that pushes the
content. Resize the preview to see the switch.

## Dual bar

Two-tier chrome, admin-console style: a permanent **icon rail** (collapsed,
tooltip labels) as primary navigation, next to a **secondary navigation
bar** listing a module's sections, both bordering the content. Two static
`ui-sidebar`s side by side — no offcanvas.

## ui-sidebar-menu

Declarative navigation menu (`UiSidebarMenuItem[]`) rendered as a **navigation
landmark**: a `<nav>` wrapping `role="list"` / `role="listitem"` containers. It handles:

- labeled **sections** (grouped navigation);
- **collapsible groups** (`toggleable`) revealing deep subtrees, with expansion
  state (`expandedKeys` two-way);
- **active-state tracking** per item (RouterLink for route links, `active` for
  manual navigation — groups containing an active descendant expand automatically);
- a trailing **badge** rendered via `ui-badge` (`badge` + `badgeLevel`) and an automatic
  "opens elsewhere" icon for external links (`external` or `target="_blank"`).

Dropped inside a `ui-sidebar`, it reads the collapsed state resolved via DI and
collapses into an **icon rail** (labels hidden, perfectly square buttons). Used standalone,
drive the rail with the `collapsed` input. In rail mode, enable **`tooltips`** to reveal
each icon's label on hover / focus (via the `[uiTooltip]` directive, positioned to the right).

## uiSidebarTrigger

Directive that **toggles** a bar from any element. It reflects the accessibility
contract between a control and the bar: `aria-controls` (panel id) and
`aria-expanded` (resolved open / collapsed state), and toggles on activation. `Enter` / `Space`
are native on a `<button>`.

```html
<button [uiSidebarTrigger]="sb" aria-label="Toggle menu">☰</button>
<ui-sidebar #sb>…</ui-sidebar>
```
