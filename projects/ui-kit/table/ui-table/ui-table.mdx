# ui-table

**Headless** data table: the component orchestrates the data pipeline
(sort → pagination), selection, expansion, scroll and pagination, while the
**row markup stays entirely in the consumer's hands** via the
`#header` / `#body` / `#footer` templates (real `<tr>/<th>/<td>`). Column
behaviors are opted into individually via companion directives
(`uiSortableColumn`, `uiSelectableRow`, `uiFrozenColumn`, `uiResizableColumn`,
`uiRowToggler`) and sub-components (`ui-table-sort-icon`,
`ui-table-checkbox`, `ui-table-header-checkbox`, `ui-table-radio`).

## Basic

A collection to display and a column template are enough.

<Canvas of={TableStories.Basic} />

```html
<ui-table [value]="products">
  <ng-template #header>
    <tr>
      <th>Code</th>
      <th>Name</th>
    </tr>
  </ng-template>
  <ng-template #body let-product>
    <tr>
      <td>{{ product.code }}</td>
      <td>{{ product.name }}</td>
    </tr>
  </ng-template>
</ui-table>
```

## Selection

### Single

One row at a time: clicking another row replaces the selection. Put
`[uiSelectableRow]` on the body template's `<tr>`.

<Canvas of={TableStories.SelectionSingle} />

### Multiple

Several rows with no dedicated column. With `metaKeySelection`, Ctrl/Cmd +
click toggles a row, Shift + click selects a range, a plain click
replaces the selection.

<Canvas of={TableStories.SelectionMultiple} />

### Checkbox

Multiple selection via checkboxes: `ui-table-header-checkbox` in the
header (select all, indeterminate on partial selection) and
`ui-table-checkbox` on each row.

<Canvas of={TableStories.SelectionCheckbox} />

### Radio

Single selection via radio buttons: `selectionMode="single"` +
`ui-table-radio` in a column.

<Canvas of={TableStories.SelectionRadio} />

### Keyboard

On `uiSelectableRow` rows: `↑`/`↓` move focus row by row,
`Space`/`Enter` toggle the focused row, `Shift + arrow` extends
the range. Combined with `selectionMode="multiple"` + `metaKeySelection`, the
whole flow is keyboard-drivable.

### Column

Selection from a column element (link, button…) is implemented via
templating: call your own handlers in the `#body` template, the
selection stays drivable via the two-way `[(selection)]`.

### Events

`rowSelect` and `rowUnselect` notify each (de)selection with
`{ originalEvent, data, index, type }`.

<Canvas of={TableStories.SelectionEvents} />

## Sort

### Single

`uiSortableColumn` + `ui-table-sort-icon` on a `<th>`: each click (or
`Enter`/`Space`) cycles ascending → descending → unsorted.

<Canvas of={TableStories.SortSingle} />

```html
<th uiSortableColumn="name">Name <ui-table-sort-icon field="name" /></th>
```

### Multiple

`sortMode="multiple"`: Ctrl/Cmd + click composes the sort across several
columns (a plain click restarts on that column alone).

<Canvas of={TableStories.SortMultiple} />

### Presort

`sortField` + `sortOrder` apply a sort on mount; the headers
stay interactive (`multiSortMeta` for multiple mode).

<Canvas of={TableStories.SortPresort} />

### Removable / custom

The simple cycle already removes the sort on the third click. For a fully
custom order, `customSort` disables the internal sort: the table
emits `sortFunction` with `{ data, mode, field, order, multiSortMeta }` and
it's up to the consumer to order `value`. For a server-side sort,
use `lazy` mode and the `sortChange` output instead (see
[Lazy / server](#lazy--server)) — don't combine with `customSort`.

## Pagination

### Basic

`paginator` + `rows` split the collection; `rowsPerPageOptions` adds
the rows-per-page selector. The bar is an instance of the standalone
**`ui-paginator`** component (see its dedicated doc), composed of `ui-button`
(circular controls, current page in `high`) and `ui-select`.

<Canvas of={TableStories.PaginationBasic} />

### Programmatic

The two-way `first` model drives pagination from the outside; any
change triggers re-pagination and `pageChange`.

<Canvas of={TableStories.PaginationProgrammatic} />

### Lazy / server

In `lazy` mode, the table no longer sorts or splits: the consumer owns
the data pipeline. `value` is the **current page** returned by the
server and `totalRecords` (server total) drives the paginator. React to
`pageChange` and `sortChange` to re-trigger the request, and enable `loading`
during the round-trip.

```html
<ui-table
  [value]="pageRows"
  lazy
  paginator
  [rows]="10"
  [totalRecords]="total"
  [loading]="loading"
  dataKey="id"
  (pageChange)="fetch($event.first, $event.rows)"
  (sortChange)="onSort($event)"
>
```

Worth knowing:

- a sort change resets `first` to `0` (the table does it itself) —
  refetch from the first page;
- the header's "select all" checkbox only covers the **current
  page**; the selection persists across pages via `dataKey`;
- with no `totalRecords`, the paginator believes the current page is the whole
  dataset (warning in dev mode);
- combined with `virtualScroll`, `lazy` keeps the existing windowed
  hydration behavior via `lazyLoad`.

## Scroll

### Vertical

`scrollable` + a fixed `scrollHeight` enable vertical scroll with a sticky
header (and sticky footer).

<Canvas of={TableStories.ScrollVertical} />

### Horizontal

When the sum of column widths exceeds the container, the table scrolls
horizontally; give each column a `min-width` to avoid
crushing (via `tableStyle` + column styles).

<Canvas of={TableStories.ScrollHorizontal} />

### Flexible

`scrollHeight="flex"` lets the viewport grow and shrink with its flex
parent, handy in a resizable modal or a split layout.

<Canvas of={TableStories.ScrollFlexible} />

## Frozen Columns

`uiFrozenColumn` freezes a column during horizontal scroll;
`alignFrozen` sticks it to the left (default) or the right. Several columns
can be frozen on each side, offsets stack up
automatically.

<Canvas of={TableStories.FrozenColumns} />

## Frozen Rows

`frozenValue` pins rows under the header during vertical scroll.

<Canvas of={TableStories.FrozenRows} />

## Row Expansion

`uiRowToggler` on the expand button + the `#expandedrow` template for the
unfolded content. The state lives in the two-way `expandedRowKeys` (requires
`dataKey`); `rowExpand`/`rowCollapse` notify each toggle.

<Canvas of={TableStories.RowExpansion} />

## Column Resize (fit)

`resizableColumns` + `uiResizableColumn` on the `<th>`s: dragging
takes width from the neighboring column, the table's total width doesn't
change. `showGridlines` makes the effect visible.

<Canvas of={TableStories.ColumnResizeFit} />

## Row Reorder

`uiReorderableRow` on the `<tr>` (with the context's `rowIndex`) makes
rows reorderable via drag and drop; an indicator marks the drop
edge. `rowReorder` emits `{ dragIndex, dropIndex, value }` with the **reordered
copy of `value`** to rebind. Designed for unsorted data.

<Canvas of={TableStories.RowReorder} />

## Column Toggle

Dynamic column display is pure templating: drive the list
of columns with a `ui-select multiple` and loop over it in `#header`
and `#body`.

<Canvas of={TableStories.ColumnToggle} />

## Loading

While loading (`loading`), the body rows are **replaced by
a waiting row** (centered `ui-spinner`) — the header stays crisp and
in place, with no translucent veil on top. Rows appear once the
data has loaded; the root gets `aria-busy="true"` and the spinner is
a named `role="status"` region.

<Canvas of={TableStories.Loading} />

## Skeleton

While a request is in flight, you can render **placeholder rows**
filled with `ui-skeleton` rather than a loading veil. Feed the
table an array of placeholders and the `#body` template places a
`ui-skeleton` per cell: the structure (headers, columns, density) stays
identical to the real content, avoiding any layout shift when the
data arrives.

<Canvas of={TableStories.Skeleton} />

## Virtual Scroll

### Preload

`virtualScroll` + `virtualScrollItemSize` (fixed height, to report on the
body template's `<tr>`) window the render to the visible viewport,
10,000 preloaded rows render as a few dozen `<tr>`s.
Requires `scrollable` + a fixed `scrollHeight`.

<Canvas of={TableStories.VirtualScrollPreload} />

### Lazy

`lazy` + the `lazyLoad { first, last }` output notify each move of
the rendered window: load the range on demand and rebind `value`.

<Canvas of={TableStories.VirtualScrollLazy} />

## States

- **Hovered row**: `table.body.surface.hover` (from `rowHover` or a selection mode).
- **Selected row**: `informative.highlightLow` family (the `table.*` category has no `selected` state).
- **Even row** (striped): `table.body.*.even`.
- **Hovered sortable header**: `table.head.surface.hover`; visible focus as an inner `global.high.stroke.focused` ring.
- Interactive states are **CSS pseudo-classes**, never props.
