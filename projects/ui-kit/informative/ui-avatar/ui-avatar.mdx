# ui-avatar

Represents a user or entity via an **image**, **initials** or an **icon**.
Headless component, styled exclusively through the design tokens (`--informative-defaultlow-*`,
`--global-border-default`, `--radius-full`…).

The **display mode is inferred from the inputs** (`image` > `label` > `icon`) — no redundant
`type` prop. A projected `[avatarBadge]` slot overlays a status indicator
(typically a `ui-badge`) in the top-right corner.

## Broken image fallback

If the image fails to load, the avatar automatically falls back to the `label` (or icon) and
emits `imageError`.

## Accessibility

<table className="doc-table">
  <thead>
    <tr>
      <th>Point</th>
      <th>Implementation</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><strong>Image mode</strong></td>
      <td>The accessible name comes from <code>alt</code> (or <code>ariaLabel</code> as a fallback). An empty <code>alt</code> makes the image decorative.</td>
    </tr>
    <tr>
      <td><strong>Label mode</strong></td>
      <td>The root carries <code>role="img"</code> + <code>aria-label</code> (<code>ariaLabel</code>, otherwise the initials); the visible initials are <code>aria-hidden</code> to avoid double reading.</td>
    </tr>
    <tr>
      <td><strong>Icon mode</strong></td>
      <td>With <code>ariaLabel</code>: <code>role="img"</code> + name. With no name: purely decorative avatar (<code>aria-hidden</code>, a warning fires in dev).</td>
    </tr>
    <tr>
      <td><strong>Badge</strong></td>
      <td>Status conveyed by color must be paired with text (e.g. <code>ariaLabel="Online"</code> on the <code>ui-badge</code>).</td>
    </tr>
  </tbody>
</table>

```html
<!-- Image avatar with notification badge -->
<ui-avatar image="/me.jpg" alt="Jane Doe">
  <ui-badge avatarBadge level="highlight" [value]="3" ariaLabel="3 notifications" />
</ui-avatar>

<!-- Initials + presence dot -->
<ui-avatar label="JD" ariaLabel="Jane Doe — online">
  <ui-badge avatarBadge level="success" size="small" ariaLabel="Online" />
</ui-avatar>
```
