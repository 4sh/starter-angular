# ui-tooltip

`[uiTooltip]` directive providing an **advisory tooltip** on any trigger
element. The behavior is **headless** and relies on **Angular CDK Overlay**:
placement, **auto-flip** when there's no room in the viewport, and
repositioning on scroll are delegated to `FlexibleConnectedPositionStrategy` (no
manual geometry). Adapted to signals.

The visual panel (bubble + arrow) is **100% driven by design tokens** from the
`informative` category (`--informative-defaulthigh-*`). One-off customization via `tooltipStyleClass`
and rich content via `TemplateRef`.

## API

<ArgTypes of={TooltipStories} />

> Content binds via the directive's alias: `[uiTooltip]="…"`. It accepts a string,
> HTML (with `escape=false`, sanitized by Angular) or a `TemplateRef` (context via
> `[tooltipContext]`).

## Placement

Four anchor sides (`top` by default). By default (`fitContent=true`), the CDK flips to
a fallback side if the tooltip would overflow the viewport, and the arrow follows
the effective side. Pass `fitContent=false` to **lock** the chosen side (no fallback).

> **`appendTo`**: the CDK attaches the overlay to a container at the `<body>` level. This is
> deliberate: it avoids clipping by an ancestor's
> `overflow`/`transform` and `z-index` conflicts. There is therefore no `appendTo` prop.

## Interactivity & customization

`autoHide=false` keeps the tooltip open while hovering it (selectable /
clickable content). For a one-off different look, set `tooltipStyleClass` on the panel and
target that class from a global stylesheet.

## Best practices

- **Native / focusable trigger**: put the directive on a `<button>`, a `ui-button`,
  a link or a field. `tooltipEvent="both"` (default) also shows it on **keyboard focus**.
- **Conciseness**: a tooltip carries brief help, never essential information or
  indispensable interactive content (use a popover/dialog for that).
- **Delays**: `showDelay` (150 ms) avoids flickering on a passing hover; `hideDelay`
  gives time to reach an interactive tooltip.

## Examples

```html
<!-- Plain text -->
<button uiTooltip="Save the document">Save</button>

<!-- Side + delays -->
<ui-button label="Help" uiTooltip="Details…" tooltipPosition="right" [showDelay]="300" />

<!-- Rich content (TemplateRef) -->
<button [uiTooltip]="tip" [tooltipContext]="{ $implicit: user }" [autoHide]="false">Profile</button>
<ng-template #tip let-u><strong>{{ u.name }}</strong><br />{{ u.role }}</ng-template>

<!-- Raw HTML (sanitized) -->
<span [uiTooltip]="'<b>Bold</b> allowed'" [escape]="false">Info</span>
```

## Theming

The panel consumes the `informative` category's design tokens **directly**
(like `ui-badge`) — surface / content / border via `--informative-defaulthigh-*`, radius
`--radius-default`, padding `--units-*`, shadow `--shadow-default-md`. No CSS hook
specific to the component: switching a theme/mode is enough to retint the tooltip.

Two structural constants stay **local** (`ui-tooltip.scss`), specific to this component:

<ConfigTable of="ui-tooltip" />

**One-off styling**: `tooltipStyleClass` adds a class on the panel; target it from a
**global** stylesheet. Since the panel uses scoped styles, the most reliable approach is to
**remap the semantic tokens** onto that class rather than overriding the properties
(variable substitution avoids any specificity conflict, and the arrow follows):

```css
.tip-highlight {
  --informative-defaulthigh-surface-default: var(--informative-highlighthigh-surface-default);
  --informative-defaulthigh-content-default: var(--informative-highlighthigh-content-default);
  --informative-defaulthigh-stroke-default:  var(--informative-highlighthigh-stroke-default);
}
```

For recurring semantic variants (`highlight`, `success`, …), the idiomatic path
would be to add a `level` input generating `._{level}` modifiers the way `ui-badge` does (not
implemented here, out of Figma's scope).
See also [Components/Configuration](?path=/docs/components-configuration--docs).
