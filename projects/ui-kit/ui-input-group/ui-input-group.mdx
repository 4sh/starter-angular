# ui-input-group

Colle un contrôle et ses **compléments** (texte, icône, bouton, case à cocher, liste
déroulante) sur une même rangée, pour qu'ils se lisent comme **un seul champ** : coins
arrondis uniquement aux extrémités, trait partagé fusionné entre deux voisins.

Composant purement présentationnel : chaque enfant conserve son API, ses états et ses
tokens. Le groupe se contente de la mise en rangée et du raccord visuel (`--radius-sm`
aux extrémités, recouvrement égal à `--stroke-default`).

Deux briques :

- **`ui-input-group`** : la rangée. Les contrôles (`ui-input`, `ui-input-number`,
  `ui-select`, `ui-button`…) y sont posés directement.
- **`ui-input-group-addon`** : une cellule non interactive (texte, icône, `ui-checkbox`,
  `ui-radio`), alignée sur la hauteur de champ.

## Multiple

Un groupe se compose en enveloppant le contrôle et ses compléments dans
`ui-input-group`. Chaque complément est un `ui-input-group-addon` : plusieurs peuvent
se suivre du même côté.

<Canvas of={InputGroupStories.Multiple} />

## Bouton

Un `ui-button` se pose **directement** dans le groupe (pas dans un add-on : il porte
déjà son propre fond et ses états), d'un côté ou de l'autre du contrôle.

<Canvas of={InputGroupStories.Button} />

## Case à cocher & radio

`ui-checkbox` et `ui-radio` se combinent avec le contrôle dans le même groupe, posés
dans un add-on.

## Liste déroulante

`ui-select` se pose directement dans le groupe, aux côtés d'autres add-ons et

## Numéro de téléphone

Indicatif international sélectionnable : drapeau + code : accolé au champ du numéro.
Les templates `#selectedItem` et `#item` de `ui-select` portent le rendu ; les drapeaux
sont des SVG locaux (`assets/img/common/svg/flags/`), décoratifs (`alt=""`).

La zone d'indicatif reste compacte alors que la liste, elle, doit afficher les noms de pays :
c'est le rôle de `panelWidth="auto"` sur le `ui-select`, qui décorrèle la largeur du panneau
de celle du champ (voir la doc de `ui-select`).

<Canvas of={InputGroupStories.PhoneNumber} />

## Taille

Le `size` du groupe n'est transmis qu'aux add-ons : chaque contrôle garde le sien, à
régler pour que les hauteurs concordent.

## Accessibilité

<table className="doc-table">
  <thead>

      <td><strong>Clavier</strong></td>

    </tr>
    <tr>
      <td><strong>Nom accessible</strong></td>
      <td>Sans libellé visible dans le groupe, chaque contrôle doit porter son <code>ariaLabel</code> (ou <code>ariaLabelledBy</code>). Un add-on décoratif : icône, symbole : ne nomme pas le champ.</td>
    </tr>
    <tr>
      <td><strong>Focus</strong></td>
      <td>L'item qui reçoit le focus est remonté au-dessus de ses voisins : sa bordure et son anneau de focus restent entièrement visibles malgré le recouvrement des bordures.</td>
    </tr>

```html
<!-- Icône + champ -->
<ui-input-group>
  <ui-input-group-addon><ui-icon name="user" size="sm" /></ui-input-group-addon>
  <ui-input placeholder="Nom d'utilisateur" ariaLabel="Nom d'utilisateur" />
</ui-input-group>

<!-- Préfixe + champ + suffixe -->
<ui-input-group>
  <ui-input-group-addon>https://</ui-input-group-addon>
  <ui-input placeholder="mon-site" ariaLabel="Adresse du site" />
  <ui-input-group-addon>.com</ui-input-group-addon>
</ui-input-group>

<!-- Champ + bouton d'action -->
<ui-input-group>
  <ui-input placeholder="Mot-clé" ariaLabel="Mot-clé" />
  <ui-button icon="magnifying-glass" ariaLabel="Rechercher" level="low" variant="outlined" />
</ui-input-group>
```

## Theming

Les items sont **projetés** : une règle CSS scopée ne peut pas les atteindre. Le groupe
pilote donc leurs coins via les custom properties exposées par les enfants
(`--ui-field-radius`, `--ui-button-radius`, `--ui-input-group-item-radius`), qui
héritent au-delà de la frontière de composant. Un composant tiers placé dans un groupe
suit le raccord dès qu'il lit `--ui-input-group-item-radius` pour son `border-radius`.
