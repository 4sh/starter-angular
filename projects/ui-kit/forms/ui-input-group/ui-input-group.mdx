# ui-input-group

Joins a control and its **add-ons** (text, icon, button, checkbox, dropdown)
on the same row, so they read as **a single field**: rounded corners only at the
ends, a shared border merged between two neighbors.

Purely presentational component: each child keeps its own API, states and
tokens. The group only handles row layout and the visual join (`--radius-sm`
at the ends, overlap equal to `--stroke-default`).

Two building blocks:

- **`ui-input-group`**: the row. Controls (`ui-input`, `ui-input-number`,
  `ui-select`, `ui-button`…) sit directly inside it.
- **`ui-input-group-addon`**: a non-interactive cell (text, icon, `ui-checkbox`,
  `ui-radio`), aligned to the field's height.

## Multiple

A group is composed by wrapping the control and its add-ons in
`ui-input-group`. Each add-on is a `ui-input-group-addon`: several can
follow each other on the same side.

<Canvas of={InputGroupStories.Multiple} />

## Button

A `ui-button` sits **directly** in the group (not in an add-on: it already
carries its own background and states), on either side of the control.

<Canvas of={InputGroupStories.Button} />

## Checkbox & radio

`ui-checkbox` and `ui-radio` combine with the control in the same group, placed
inside an add-on.

<Canvas of={InputGroupStories.CheckboxRadio} />

## Dropdown

`ui-select` sits directly in the group, alongside other add-ons and
controls.

<Canvas of={InputGroupStories.Select} />

## Phone number

Selectable international dial code: flag + code, joined to the number field.
`ui-select`'s `#selectedItem` and `#item` templates carry the rendering; the flags
are local SVGs (`assets/img/common/svg/flags/`), decorative (`alt=""`).

The dial-code zone stays compact while the list, on the other hand, must display country
names: that's the role of `panelWidth="auto"` on the `ui-select`, which decouples the panel's
width from the field's (see `ui-select`'s docs).

<Canvas of={InputGroupStories.PhoneNumber} />

## Size

The group's `size` is only forwarded to the add-ons: each control keeps its own, to
be set so heights line up.

    </tr>
    <tr>
      <td><strong>Accessible name</strong></td>
      <td>With no visible label in the group, each control must carry its own <code>ariaLabel</code> (or <code>ariaLabelledBy</code>). A decorative add-on — icon, symbol — doesn't name the field.</td>
    </tr>
    <tr>
      <td><strong>Focus</strong></td>
      <td>The item that receives focus is raised above its neighbors: its border and focus ring stay fully visible despite the border overlap.</td>
    </tr>
  </tbody>

```html
<!-- Icon + field -->
<ui-input-group>
  <ui-input-group-addon><ui-icon name="user" size="sm" /></ui-input-group-addon>
  <ui-input placeholder="Username" ariaLabel="Username" />
</ui-input-group>

<!-- Prefix + field + suffix -->
<ui-input-group>
  <ui-input-group-addon>https://</ui-input-group-addon>
  <ui-input placeholder="my-site" ariaLabel="Website address" />
  <ui-input-group-addon>.com</ui-input-group-addon>
</ui-input-group>

<!-- Field + action button -->
<ui-input-group>
  <ui-input placeholder="Keyword" ariaLabel="Keyword" />
  <ui-button icon="magnifying-glass" ariaLabel="Search" level="low" variant="outlined" />
</ui-input-group>
```

## Theming

The items are **projected**: a scoped CSS rule can't reach them. The group
therefore drives their corners via custom properties exposed by the children
(`--ui-field-radius`, `--ui-button-radius`, `--ui-input-group-item-radius`), which
inherit across the component boundary. A third-party component placed in a group
follows the join as soon as it reads `--ui-input-group-item-radius` for its `border-radius`.
