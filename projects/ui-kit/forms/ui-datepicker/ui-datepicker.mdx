# ui-datepicker

Headless **date / month / year** (and optional **time**) picker. A read-only
[`ui-input`](?path=/docs/components-ui-forms-ui-input--docs) trigger field opens
a token-styled calendar (`form.*` / `actions.*` tokens) in an Angular CDK overlay — or renders
**inline**. `single` / `multiple` / `range` selection, drill-down views (day → month → year),
`MonthPicker` / `YearPicker` modes, several months side by side, monthly navigation, roving
focus and full keyboard support (WAI-ARIA date picker pattern).
`p-datepicker`.

Wired as a `ControlValueAccessor` (Signal Forms `[formField]`, `[(ngModel)]` or `[formControl]`) on
[`BaseFormField`](?path=/docs/components-ui-forms-ui-input--docs): `label`, `helperText`/`errorText`,
`level`, validation and the `disabled`/`readonly` states are shared with the other fields.

**Value: `Date` or an ISO string, depending on `valueType` (required, no default).** The
`valueType: 'date' | 'iso'` input is **required**: no implicit value, to force an
explicit choice rather than a silent default that wouldn't match the model's actual type. `writeValue`
always accepts either `Date` **or** an ISO `"yyyy-MM-dd"` string (`"yyyy-MM-ddTHH:mm"` with
`showTime`/`timeOnly`), auto-detected — whichever the app has on hand. What gets
**emitted** (`valueChange`, `dateSelect`, hence what lands in the `FormControl`) strictly follows
`valueType`, never a silent mix of the two shapes:

- **`'date'`** — the value stays a `Date` end to end, normalized to midnight when
  no time is shown (`!showTime && !timeOnly`). Designed for a DTO round-tripped by
  `class-transformer` (`@Type(() => Date)`): the form works directly with the DTO's `Date`,
  no conversion needed on the app side — serializing to the backend's JSON stays
  `class-transformer`'s responsibility, not the field's.
- **`'iso'`** — the value is a `"yyyy-MM-dd"` string (`string[]` in `multiple`/`range`). For
  a field reading/writing directly against a backend `LocalDate`, with no DTO/`class-transformer`
  in between (e.g. a search filter). Always built from the `Date`'s local components
  (`getFullYear()/getMonth()/getDate()`), never `date.toISOString()` (which switches to
  UTC and can shift the day depending on the local timezone).

`Date` remains the internal representation for all calendar computation either way — only the
`writeValue`/`commit` boundary converts, in one direction or the other depending on `valueType`.

## Selection: single / multiple / range

`selectionMode` sets how much is selected. The model's value is a `Date`/ISO string
(depending on `valueType`) in `single`, an array in `multiple` (toggles on click, the panel stays
open) and a `[start, end]` array in `range` (1st click = start, 2nd = end, the
interval is highlighted).

## Views & modes (day → month → year)

Clicking the header's **title** moves up a level: day → month selection → year
selection. The `view` input sets the base granularity: `date` (default), `month`
(**MonthPicker**) or `year` (**YearPicker**). In month/year mode, clicking directly selects
a month / a year.

`numberOfMonths` displays N month panels side by side, separated by a rule, with month

## Opening (placement)

The panel opens below the field and **flips above automatically** when there's no room
below (CDK Overlay). `autoFlip="false"` locks the opening downward.

## Date & time

`showTime` adds a time row as **vertical steppers** (↑/↓ chevrons around
each HH : MM unit — `spinbutton` ARIA pattern, drivable with the arrow keys);
`hourFormat="12"` adds an AM/PM selector. `timeOnly` hides the calendar. When `showTime` is
active, the panel **stays open** after picking a day (to set the time) even with `closeOnSelect`.

## Selection constraints

`minDate` / `maxDate` bound the range; `disabledDays` (0 = Sunday … 6 = Saturday) and
`disabledDates` (specific dates) neutralize cells. `showButtonBar` adds the
"Today" / "Clear" actions.

`minDate`, `maxDate` and each `disabledDates` entry equally accept a `Date` **or**
an ISO `"yyyy-MM-dd"` string (both shapes are mixable in `disabledDates`) — handy
when the bounds already come from a backend in the same format as the value. A malformed
string silently degrades to "no constraint" rather than throwing.

## Manual input (`allowInput`)

By default the field is read-only: the date can only be picked from the panel.
Enable `allowInput` to allow **keyboard typing** in the field (`single` mode
only). The text is parsed on **blur** and on **Enter**; an invalid entry reverts
to the last displayed value. `↓` opens the panel and enters the grid.

When `showTime` is active (outside `timeOnly`), the mask also covers the hour/minute
segments (and AM/PM in `hourFormat="12"`): `allowInput` remains usable to type the date **and** the
time in one go. `allowInput` has, however, **no effect in `timeOnly`** (no parser/formatter
dedicated to a time-only value): the field there always stays read-only.

When `allowInput` is active (and with no custom `dateFormat`), the value displays in the
locale's **numeric format** (e.g. `08/07/2026`) for a reliable round trip with the parser.

The **"/" separators insert automatically while typing**, as soon as a segment (day,
month) is complete — the same idea as a credit card expiry field (`0812…` →
`08/12…`). The year segment stays deliberately free (no forced "/" after 2 or 4 digits):
strict validation happens at parse time (blur/Enter), not in this cosmetic mask. This
behavior shares its engine with [`ui-input-mask`](?path=/docs/components-ui-forms-ui-input-mask--docs)
(`mask-engine.ts`) and disables itself automatically as soon as a custom `parseDate` is supplied (a
non-numeric format would make the auto-slash wrong).

> **Field order follows the resolved locale** (`locale`, or `LOCALE_ID` failing that). In
> `fr-FR` it's **dd/mm/yyyy**; in `en-US` it's **mm/dd/yyyy** — auto-formatting follows the same
> order. If `LOCALE_ID` isn't configured, Angular falls back to `en-US`: pass `locale="fr-FR"`
> (or configure `LOCALE_ID`) to type in DD/MM/YYYY. The **placeholder is derived
> automatically** from this order when not supplied, so it never shows a misleading
> format.

Provide `parseDate` `(value: string) => Date | null` for custom parsing (symmetric
to `dateFormat`). These two hooks work in `Date` (display/free typing only) — they
are never round-tripped through the CVA, so the ISO contract doesn't concern them.

## Templates

Two extension points via projected `<ng-template>`s, resolved with `contentChild`:

- **`#date`** — custom day cell. Context: `$implicit` = day descriptor
  (`{ day, month, year, otherMonth, today, selected, disabled, rangeStart, rangeEnd, inRange }`)
  and `selected` (boolean). Ideal for event dots, colored weekends, etc.
- **`#buttonbar`** — custom button bar. Context: `todayCallback` and `clearCallback`
  (functions to wire to `(click)`).

<Canvas of={DatepickerStories.DateTemplate} />
<Canvas of={DatepickerStories.CustomButtonBar} />

```html
<!-- Custom day cell -->
<ui-datepicker [(ngModel)]="date" valueType="date">
  <ng-template #date let-d let-selected="selected">
    <span>{{ d.day }}</span>
    @if (hasEvent(d)) { <span class="dot"></span> }
  </ng-template>
</ui-datepicker>

<!-- Custom button bar -->
<ui-datepicker [(ngModel)]="range" valueType="date" selectionMode="range" showButtonBar>
  <ng-template #buttonbar let-todayCallback="todayCallback" let-clearCallback="clearCallback">
    <ui-button size="small" label="Today" (buttonClick)="todayCallback($event)" />
    <ui-button size="small" level="error" icon="xmark" iconOnly ariaLabel="Clear" (buttonClick)="clearCallback($event)" />
  </ng-template>
</ui-datepicker>
```

## Forms

The component is a `ControlValueAccessor`: it wires up with no extra code to
**Signal Forms** (`@angular/forms/signals`, `[formField]` directive, stable since Angular 22)
via native CVA interop, as well as to template-driven (`[(ngModel)]`) and reactive
(`[formControl]`) forms.

<Canvas of={DatepickerStories.SignalForms} />

```html
<!-- Signal Forms, class-transformer DTO (birth: Date) -->
<ui-datepicker [formField]="birth" valueType="date" label="Birth date" />

<!-- Reactive forms, class-transformer DTO (form.controls.birth: FormControl<Date | null>) -->
<ui-datepicker formControlName="birth" valueType="date" label="Birth date" [maxDate]="today" required />

<!-- Reactive forms, direct ISO value (form.controls.birth: FormControl<string | null>) -->
<ui-datepicker formControlName="birth" valueType="iso" label="Birth date" required />

<!-- Date + time, ngModel -->
<ui-datepicker [(ngModel)]="appointment" valueType="date" label="Appointment" showTime hourFormat="12" showButtonBar />

<!-- Inline (no overlay) -->
<ui-datepicker [(ngModel)]="date" valueType="date" inline />
```

> **Scope / choices**: the trigger field is **read-only by default** (picking via the
> calendar only); `allowInput` (`single` mode, outside `timeOnly`) opens it to **masked
> keyboard input** — see [Manual input](#manual-input-allowinput). The view drawer
> (day → month → year) and roving keyboard focus are active in **single-month** — now also
> in the `MonthPicker`/`YearPicker` grids; in multi-month the headers are fixed with arrows
> at the ends. Interactive states (hover/focus/pressed) are **CSS pseudo-classes**
> driven by tokens, not props. Customization via `panelStyleClass`, `#date`,
> `#buttonbar`.
