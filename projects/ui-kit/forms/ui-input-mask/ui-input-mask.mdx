# ui-input-mask

**Masked** field built on the [`ui-field`](?path=/docs/components-ui-forms-ui-field--docs) shell.
The `mask` pattern automatically inserts literals while typing:

      <th>Accepts</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>9</code></td>
      <td>a digit <code>0-9</code></td>
    </tr>
    <tr>
      <td><code>a</code></td>
      <td>a letter <code>a-z A-Z</code></td>
    </tr>
    <tr>
      <td><code>*</code></td>
      <td>an alphanumeric character</td>
    </tr>
    <tr>
      <td><em>other</em></td>
      <td>literal, inserted automatically (<code>/</code>, <code>-</code>, space, <code>(</code>, <code>)</code>…)</td>
    </tr>
  </tbody>
</table>

Model value = masked string (`12/09/2024`) by default, or raw (`12092024`) with `unmask`.

## Bounded values (`ranges`)

The mask describes the **shape**. The `ranges` input bounds
each **numeric segment** — a run of consecutive `9` tokens — in **mask order**,
as `min-max` pairs separated by spaces (`*` leaves a segment unbounded):

<table className="doc-table">
  <thead>
    <tr><th>Mask</th><th><code>ranges</code></th><th>Effect</th></tr>
  </thead>
  <tbody>
    <tr>
      <td><code>99:99</code></td>
      <td><code>0-23 0-59</code></td>
      <td>24h time — <code>33:33</code> becomes impossible to type</td>
    </tr>
    <tr>
      <td><code>99/99/9999</code></td>
      <td><code>1-31 1-12 1900-2100</code></td>
      <td>day / month / year</td>
    </tr>
    <tr>
      <td><code>99:99:99</code></td>
      <td><code>* 0-59 0-59</code></td>
      <td>only the 2nd and 3rd segments are bounded</td>
    </tr>
  </tbody>
</table>

Checking happens **while typing**, ahead of time: a character is only accepted if at least
one way remains to complete the segment within the range. For `0-23`, `3` is rejected outright
(`30`-`39` all fall outside the range); `2` passes, then `4` is rejected and `3` is accepted. A
**fully filled** segment is therefore always within its range — the lower bound, on the
other hand, remains reachable by prefix (`0` is accepted on `1-31`, awaiting the next `1`-`9`).

<Canvas of={MaskStories.Time} />

> `ranges` only bounds **numeric** segments (`9`); the `a`/`*` tokens are ignored in the
> numbering. Bounds also apply to values **written by the form**
> (`writeValue`), just like the character filtering already in place. An **incomplete**
> segment (`9_:__`) remains possible: completeness is the form's validation's concern
> (`required`, or a dedicated validator), not the mask's.

## Forms

The component is a `ControlValueAccessor`: it wires up with no extra code to
**Signal Forms** (`@angular/forms/signals`, `[formField]` directive, stable since Angular 22)
via native CVA interop, as well as to template-driven (`[(ngModel)]`) and reactive
(`[formControl]`) forms.

## Accessibility & notes

<table className="doc-table">
  <thead>
    <tr><th>Point</th><th>Implementation</th></tr>

  <tbody>
    <tr>
      <td><strong>Label / helper / error</strong></td>
      <td>Via the `ui-field` shell: label linked via <code>for</code>/<code>id</code>, message linked via <code>aria-describedby</code>, <code>aria-invalid</code> on error.</td>
    </tr>
    <tr>
      <td><strong>Input</strong></td>
      <td>Literals (`/`, `-`…) are inserted automatically; characters that don't match the token — or fall outside the <code>ranges</code> bounds — are ignored.</td>
    </tr>
  </tbody>
</table>

```html
<!-- Signal Forms -->
<ui-input-mask [formField]="field" label="Date" mask="99/99/9999" placeholder="dd/mm/yyyy" />

<ui-input-mask formControlName="birthDate" label="Date" mask="99/99/9999" placeholder="dd/mm/yyyy" iconLeft="calendar" />
<ui-input-mask [(ngModel)]="phone" label="Phone" mask="(999) 999-9999" />
<ui-input-mask [(ngModel)]="iban" label="IBAN" mask="FR99 9999 9999 9999" [unmask]="true" />

<!-- Bounded values -->
<ui-input-mask [(ngModel)]="time" label="Time" mask="99:99" ranges="0-23 0-59" />
<ui-input-mask [(ngModel)]="birth" label="Date" mask="99/99/9999" ranges="1-31 1-12 1900-2100" />
```

> Caret: after masking, the cursor is repositioned based on the number of data characters
> before it (auto-inserted literals skipped) — editing **in the middle** of the string keeps
> a consistent position, not just at the end of input.

## Theming

No overridable local variables: the box comes from the `ui-field` shell. Configuration goes
through its variables (shared [Forms](?path=/docs/components-configuration-forms--docs) group),
detailed in [`ui-input`](?path=/docs/components-ui-forms-ui-input--docs)'s docs. See
[how configuration works](?path=/docs/components-configuration--docs).
