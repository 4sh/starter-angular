# ui-select

Headless **dropdown** built on the shared
[`ui-field`](?path=/docs/components-ui-forms-ui-field--docs) shell (label + box + helper) and a
token-styled options panel in a CDK overlay.

<Canvas of={SelectStories.Basic} />

## Basic

Control driven by `ngModel` (or reactive forms) with an `options` collection. When the
options are objects, `optionLabel` and `optionValue` (dotted paths) indicate what to
display and what to carry in the model. With **primitives** (an array of strings),
neither is needed.

```html
<ui-select label="City" [(ngModel)]="city" [options]="cities" optionLabel="name" optionValue="code" />
<ui-select label="Fruit" [(ngModel)]="fruit" [options]="['Apple', 'Pear', 'Cherry']" />
```

## Multiple

With `multiple`, several items can be selected: the model becomes an **array** and
the panel stays open after each toggle. Combine `checkmark` for a check indicator
and the `#selectedItem` template to customize the trigger's display.

`maxSelectedLabels` limits the number of items shown in the field: beyond that, the rest
collapses into an `overflowLabel` indicator (`(+{0} more)` by default, `{0}` = hidden count).
Under constrained width, the box switches to **automatic height** and values wrap to the
next line instead of being truncated. `Backspace` on the trigger removes the last selected
item.

<Canvas of={SelectStories.Multiple} />

## Checkmark

Another way to highlight the selection: a **check** at the end of the row
(in addition to the `form.high.surface.hover` background + `checked` text).

<Canvas of={SelectStories.Checkmark} />

## Checkbox Selection

Multiple selection with **checkboxes** (`multiple` + `checkbox`) and `#item` /
`#header` templates. The checkboxes are purely visual (`aria-hidden`): the accessible state is
carried by `aria-selected` on the option itself.

<Canvas of={SelectStories.CheckboxSelection} />

## Chips

In `multiple` mode, the `#selectedItem` template is rendered **once per selected
value** — ideal for displaying the selection as
[`ui-chip`](?path=/docs/components-ui-informative-ui-chip--docs). The context exposes a
**`remove`** callback: wire it to the chip's remove action (`removable` +
`(remove)="remove()"`) to remove a value **directly from the field**. Chips are
rendered **next to** the combobox button (valid interactive HTML); on the keyboard, `Backspace`
removes the last item. Chips wrap under constrained width.

```html
<ng-template #selectedItem let-city let-remove="remove">
  <ui-chip [label]="city.name" size="small" [removable]="true" (remove)="remove()" />
</ng-template>
```

<Canvas of={SelectStories.Chips} />

## Clear

With `showClear`, a clear action (×) appears when a value is set —
a **subtle** affordance built into the field (color feedback + focus ring, no button
background), a native button with `aria-label`, hidden if the field is disabled/readonly. The
value goes back to `null`.

<Canvas of={SelectStories.Clear} />

## Filter

`filter` enables **built-in filtering** (case- and accent-insensitive). The
filter field takes focus on open (`autofocusFilter`), `filterBy` lists the compared fields
(label by default), `resetFilterOnHide` clears the filter on close, and `emptyFilterMessage`
displays when nothing matches.

<Canvas of={SelectStories.Filter} />

The `#item` template replaces an option's rendering

## Selected Value

The `#selectedItem` template customizes the **value displayed in the field** (not just
in `multiple` mode: it also applies to single-select). Combined with `#item`, you get
identical rich rendering for the list option and for the selected value (context:
`$implicit`/`option`, `index`, `remove` callback).

```html
<ui-select [(ngModel)]="lang" [options]="languages" optionLabel="label" optionValue="value" [filter]="true" [checkmark]="true">
  <ng-template #selectedItem let-lang>
    <span class="row"><ui-icon [name]="lang.icon" size="sm" /> {{ lang.label }}</span>
  </ng-template>
  <ng-template #item let-lang>
    <span class="row"><ui-icon [name]="lang.icon" size="sm" /> {{ lang.label }}</span>
  </ng-template>
</ui-select>
```

<Canvas of={SelectStories.SelectedValue} />

## Group

With `group`, `options` is a nested structure: `optionGroupLabel` (default `label`) and
`optionGroupChildren` (default `items`) describe each group. Headers are
customizable via the `#group` template. Groups emptied by the filter disappear.

<Canvas of={SelectStories.Group} />

## Sizes

`size` offers `small` as an alternative to the base size (`default`) — like every field
in the kit (the design system doesn't define a `large` size).

<Canvas of={SelectStories.Sizes} />

## Panel Width

By default the panel matches the field's width. When the field is deliberately
compact — a phone code in a `ui-input-group`, for example — but the
options aren't, `panelWidth` decouples the two: `auto` sizes the panel to
its content **while never going below the field's width**, a CSS size (`320px`) fixes it.

<Canvas of={SelectStories.PanelWidth} />

## Disabled

`disabled` disables the field (**native** attribute on the trigger: neither editable, nor
focusable). A single option can be disabled via `optionDisabled` (or a `disabled` key
on the object).

<Canvas of={SelectStories.Disabled} />

## Invalid

The error style applies via `invalid` — or **automatically** when the attached control
(reactive forms / `ngModel`) is invalid and touched/dirty. `errorText` then replaces the
helper, `aria-invalid` is set on the trigger.

<Canvas of={SelectStories.Invalid} />

## Focus Behavior

Visual focus behavior is configured with `autoOptionFocus` (focus the first option
on open), `selectOnFocus` (select while navigating by keyboard, single mode) and
`focusOnHover` (follow mouse hover, active by default).

<Canvas of={SelectStories.FocusBehavior} />

## Editable

With `editable`, the trigger becomes a real `<input>`: typing **directly** sets the
model's value **and opens the panel filtering matching options** (autocomplete-style).
Selecting a suggestion replaces the text with the option's label;
closing the panel keeps the typed text as is (single mode only).

<Canvas of={SelectStories.Editable} />

## Loading State

`loading` replaces the chevron with a
[`ui-spinner`](?path=/docs/components-ui-informative-ui-spinner--docs) (`role="status"`
live region).

<Canvas of={SelectStories.Loading} />

## Virtual Scroll

For large lists, `virtualScroll` renders options in a **virtual scroll
viewport** (CDK): only a subset is present in the DOM.
`virtualScrollItemSize` sets a row's height (px) — group headers included (they
are aligned to this height in this mode). `aria-setsize`/`aria-posinset` preserve
position announcements.

<Canvas of={SelectStories.VirtualScroll} />

## Lazy Virtual Scroll

With `lazy` (+ `virtualScroll`), the `lazyLoad` output emits the **rendered range**
(`{ first, last }`) on every scroll: load data on demand and feed it back
into `options`.

<Canvas of={SelectStories.LazyVirtualScroll} />

> **Security & perf**: no `innerHTML` — all content (labels, filter, messages) is
> interpolated, hence escaped by Angular. Lists are recomputed in `computed()` (no
> rescan per cycle), virtual scrolling bounds the DOM to the visible rows, and `lazy`
> defers data loading to scroll time.

```html
<!-- Signal Forms -->
<ui-select [formField]="city" label="City" [options]="cities"
           optionLabel="name" optionValue="code" />

<!-- Reactive forms + automatic error -->
<ui-select formControlName="country" label="Country" [options]="countries"
           optionLabel="name" optionValue="iso" required errorText="Selection required" />

<!-- Rich multi-select: groups + checkboxes + filter -->
<ui-select [(ngModel)]="cities" [options]="groupedCities" [group]="true"
           optionLabel="name" optionValue="code"
           [multiple]="true" [checkbox]="true" [filter]="true" />

<!-- Large list loaded on demand -->
<ui-select [(ngModel)]="item" [options]="rows" [virtualScroll]="true"
           [virtualScrollItemSize]="40" [lazy]="true" (lazyLoad)="fetchRange($event)" />
```

> Architecture: `ui-select` shares the `ui-field` shell (label + box + helper + states) and the
> `BaseFormField` base (CVA + validation) with the other fields. The panel reuses the
> shared `utils.overlay-panel` shell (like `ui-menu` and `ui-datepicker`), in the `form.*`
> token family.
