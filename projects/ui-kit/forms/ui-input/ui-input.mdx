# ui-input

Champ **texte** (text/email/tel/url/search/**password**) bâti sur le shell partagé
[`ui-field`](?path=/docs/components-ui-forms-ui-field--docs) (label + boîte + helper) et un
`<input>` natif. Couleurs via tokens `form.*`, bordure pilotée par le `level`. Slots
optionnels : icône gauche, unité suffixe, et **zone d'action droite**.

Autonome, `[(ngModel)]` ou reactive forms (`ControlValueAccessor` via `BaseFormField`).
Pour les nombres → [`ui-input-number`](?path=/docs/components-ui-forms-ui-input-number--docs) ;
pour les masques → [`ui-input-mask`](?path=/docs/components-ui-forms-ui-input-mask--docs).

## Libellé flottant

`floatLabel` fait descendre le libellé **dans** le champ, où il tient le rôle du placeholder,
et le fait remonter dès que le champ prend le focus ou porte une valeur. Trois positions
hautes, communes à tous les champs bâtis sur `ui-field` :

<table className="doc-table">
  <thead>
    <tr>
      <th>Valeur</th>
      <th>Position haute</th>
      <th>Effet sur la mise en page</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>over</code></td>
      <td>Au-dessus de la boîte, sur la rangée d'un libellé classique, mais aligné
      horizontalement sur le contrôle plutôt que sur le bord du champ.</td>
      <td>Une bande de la hauteur du libellé est réservée au-dessus du champ : le libellé
      sort de la boîte sans jamais recouvrir ce qui précède, et rien ne bouge autour.</td>
    </tr>
    <tr>
      <td><code>in</code></td>
      <td>Dans une bande réservée en haut de la boîte.</td>
      <td>La boîte grandit de cette bande, de sorte que la rangée du contrôle garde sa
      hauteur habituelle. La bande est réservée par le contrôle, pas par la boîte : seul
      le texte saisi descend sous le libellé, tandis qu'affixes, unités, zones d'action et
      libellé au repos restent centrés sur la boîte.</td>
    </tr>
    <tr>
      <td><code>on</code></td>
      <td>À cheval sur le trait supérieur, qu'il entaille.</td>
      <td>Aucune. L'entaille est peinte avec le fond du champ
      (<code>--form-high-surface-*</code>) : un champ posé sur un autre fond demande donc
      de retoucher ce token avec lui.</td>
    </tr>
  </tbody>
</table>

<Canvas of={InputStories.FloatLabel} />

```html
<ui-input [(ngModel)]="name" floatLabel="on" label="Nom" />
```

Le libellé remonte au **focus**, dès qu'une **valeur** est présente, tant qu'un
**panneau** ouvert retient le champ (un déclencheur comme `ui-datepicker` confie le focus
à son calendrier, sans cesser d'être actif pour autant), et sur **autofill** du navigateur
(qui ne déclenche aucun évènement de saisie). Il redescend quand le champ est vide, sans
focus et sans panneau. Seuls la position et l'échelle du libellé
changent : pas de `font-size` animée, donc aucune reprise de mise en page pendant le
trajet, et la transition est coupée quand l'utilisateur demande moins d'animation.

Avec une **icône gauche**, le libellé au repos se décale pour la laisser voir. Ce retrait est
calé sur l'échelle des icônes (`--ui-field-float-label-indent`), pas mesuré : un glyphe plus
large que son pas d'échelle, ou un affixe projeté d'une autre nature, se règle par ce hook.

> Au repos, le libellé flottant occupe la place du `placeholder`. Celui-ci est donc
> **neutralisé** tant que `floatLabel` et `label` sont tous les deux renseignés, deux textes
> superposés dans la même boîte n'étant lisibles ni l'un ni l'autre. `floatLabel` sans
> `label` ne fait rien : le champ garde son rendu habituel, placeholder compris.

## Slots & zone d'action

L'icône droite devient une **zone d'action** (bouton carré pleine hauteur, focusable) dès qu'on
renseigne `iconRightAriaLabel` ; le clic émet `iconRightClick`.

## Icônes : template ponctuel, ou famille de zone

`iconLeft` / `iconRight` prennent un **nom** d'icône ; deux leviers permettent d'aller au-delà,
selon l'échelle visée.

**Une icône → un `<ng-template>`.** Les deux zones acceptent `#iconLeft` / `#iconRight`, qui
remplacent le markup rendu : icône d'une autre famille, SVG de marque, contenu libre. La zone
d'action droite garde son `<button>` accessible (`iconRightAriaLabel` + `iconRightClick`) : seul
son contenu change. Contexte reçu : `$implicit` = le nom configuré sur cette zone, `size` = la
taille calée sur le champ, `disabled` = l'état du champ.

<Canvas of={InputStories.IconTemplate} />

```html
<ui-input [(ngModel)]="theme" label="Thème" iconRight="sun" iconRightAriaLabel="Inverser le thème">
  <ng-template #iconRight let-name let-size="size">
    <ui-icon [name]="name" family="material" [size]="size" />
  </ng-template>
</ui-input>
```

**Une zone → la directive `uiIconFamily`.** Elle bascule d'un coup toutes les icônes descendantes,
sans en viser une en particulier — voir
[`ui-icon`](?path=/docs/components-ui-ui-icon--docs) pour les trois échelles et le critère
de choix.

<Canvas of={InputStories.ScopedIconFamily} />

> Les templates sont aussi câblables **par code** (`iconLeftTemplate` / `iconRightTemplate`) : c'est
> par là qu'un composant composite forwarde le sien — `ui-datepicker` expose ainsi `#icon` sur son
> déclencheur.

## Formulaires

Le composant est un `ControlValueAccessor` : il se branche sans code additionnel aux
**Signal Forms** (`@angular/forms/signals`, directive `[formField]`, stables depuis Angular 22)
via l'interop CVA native, ainsi qu'aux formulaires template-driven (`[(ngModel)]`) et réactifs
(`[formControl]`).

<Canvas of={InputStories.SignalForms} />

```html
<!-- Signal Forms -->
<ui-input [formField]="field" label="Nom" placeholder="Votre nom" />
```

    </tr>
    <tr>
      <td><strong>Aide & erreur</strong></td>
      <td><code>ui-helper</code> relié par <code>aria-describedby</code>. <code>aria-invalid</code> + bordure erreur, automatique quand le contrôle est invalide et touché/modifié.</td>
    </tr>
    <tr>
      <td><strong>Zone d'action</strong></td>
      <td>Bouton natif (dans l'ordre de tabulation) avec <code>aria-label</code> obligatoire. Icônes décoratives en <code>aria-hidden</code>.</td>
    </tr>
    <tr>
      <td><strong>Désactivé</strong></td>
      <td><code>disabled</code> natif (pas seulement visuel) ; couleurs via tokens <code>--form-*-disabled</code>.</td>
    </tr>
  </tbody>

```html
<!-- Reactive forms + message d'erreur -->
<ui-input formControlName="email" type="email" label="Email" errorText="Adresse invalide" required />

<!-- Recherche : icône « effacer » actionnable, visible seulement avec du texte -->
<ui-input
  [(ngModel)]="q"
  label="Recherche"
  iconLeft="magnifying-glass"
  [iconRight]="q ? 'xmark' : undefined"
  iconRightAriaLabel="Effacer"
  (iconRightClick)="q = ''"
/>
```

> Architecture : `ui-input`, `ui-input-number` et `ui-input-mask` partagent le shell `ui-field`
> (label + boîte + helper + états) et la base `BaseFormField` (CVA + validation). Le
> sous-composant Figma `_ui-input-content` est porté nativement par l'`<input>`.

## Theming

`ui-input`, `ui-input-mask` et `ui-input-number` n'ont **aucune variable locale surchargeable** :
leur boîte est fournie par le shell `ui-field`, stylé via les mixins `utils.field-*`. Toute la
configuration passe donc par les variables locales de `ui-field.scss` (qui pointent vers le groupe
partagé [Forms](?path=/docs/components-configuration-forms--docs)). Voir aussi le
[fonctionnement de la configuration](?path=/docs/components-configuration--docs).
