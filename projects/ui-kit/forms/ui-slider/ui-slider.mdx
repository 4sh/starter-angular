# ui-slider

The `ui-slider` component lets you pick a numeric value (or a range)
by dragging a handle along a track. It implements the
WAI-ARIA "slider" pattern: each handle carries `role="slider"` with `aria-valuemin`,
`aria-valuemax`, `aria-valuenow` and `aria-orientation`, and is fully keyboard-drivable.
Pointer interactions (mouse, touch, stylus) go through a single code
path (`PointerEvent` + pointer capture).

## Step

The granularity of every move (drag and keyboard) is set by `step`.

<Canvas of={SliderStories.Step} />

## Range

With `range`, the slider shows two handles defining two values. The model
must then be a `[start, end]` array.

<Canvas of={SliderStories.Range} />

### Gap between handles

`minStepsBetweenHandles` sets the minimum number of steps kept between the two
handles in `range` mode.

<Canvas of={SliderStories.HandlesDistance} />

## Controlled

The slider shares its model with a [`ui-input-number`](?path=/docs/components-ui-forms-ui-input-number--docs)
via a two-way binding: the two stay in sync.

<Canvas of={SliderStories.Controlled} />

## Value Change

`sliderChange` is emitted **continuously** while moving, whereas `slideEnd`
is only emitted once the drag (or the track click) is **complete**.

<Canvas of={SliderStories.ValueChange} />

## Marks

`marks` shows a tick per step along the track (bounded to protect the DOM:
disabled beyond 100 steps).

<Canvas of={SliderStories.Marks} />

## Custom

The component is headless: beyond themes/tokens, three **structural hooks**
(CSS custom properties) let you retune it per instance without an SCSS override.

```html
<ui-slider [(ngModel)]="value"
           style="--ui-slider-thickness: 4px; --ui-slider-handle-size: 28px;" />
```

<Canvas of={SliderStories.Custom} />

## Orientation

`orientation="vertical"` switches the layout (and adapts the arrow keys). The
length in vertical mode is set via `--ui-slider-length`.

## Forms

The component is a `ControlValueAccessor`, so it wires up to every form
API with no extra code. Signal Forms (`@angular/forms/signals`,
`[formField]` directive), stable since Angular 22, work via the
native CVA interop layer, with no component rewrite.

<Canvas of={SliderStories.SignalForms} />
<Canvas of={SliderStories.TemplateDriven} />
<Canvas of={SliderStories.ReactiveForms} />

```html
<!-- Signal Forms -->
<ui-slider [formField]="volume" ariaLabel="Volume" />

<!-- Template-driven -->
<ui-slider [(ngModel)]="level" name="level" required ariaLabel="Level" />

<!-- Reactive -->
<ui-slider [formControl]="levelCtrl" ariaLabel="Level" />
```

- The **error style applies automatically** when the attached control is invalid
  **and** touched/dirty; `invalid` lets you force it.
- `disabled` disables the control (via the input or `control.disable()`).

## Theming

Local variables at the top of `ui-slider.scss`. Those pointing to `utils.*`
are the **per-component adjustment point**; see the shared
[Forms](?path=/docs/components-configuration-forms--docs) group and
[how configuration works](?path=/docs/components-configuration--docs). The
`--ui-slider-*` hooks can be overridden per instance (see [Custom](#custom)).
