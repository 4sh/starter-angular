# ui-autocomplete

**Suggestion** field built on the shared
[`ui-field`](?path=/docs/components-ui-forms-ui-field--docs) shell (label + box + helper) and a
token-styled suggestions panel in a CDK overlay. The trigger is a native `<input>`
following the WAI-ARIA **combobox** pattern (`aria-activedescendant`: focus never leaves
the input, suggestions only receive visual focus).

<Canvas of={AutocompleteStories.Basic} />

## Basic

Control driven by `ngModel` (or Signal Forms / reactive forms — see
[Forms](#forms)). Typing emits `completeMethod` — the
request is **debounced** (`delay`, 300 ms by default) and triggered from
`minLength` characters (1 by default). The parent then sets `suggestions` with the
results. `optionLabel` indicates which property to display when suggestions are
objects.

```html
<ui-autocomplete
  label="Country"
  [(ngModel)]="country"
  [suggestions]="results()"
  optionLabel="name"
  (completeMethod)="search($event)"
/>
```

```ts
search(event: AutocompleteCompleteEvent): void {
  const q = event.query.toLowerCase();
  this.results.set(ALL.filter((c) => c.name.toLowerCase().includes(q)));
}
```

## Dropdown

`dropdown` shows a trigger button next to the input. `dropdownMode` sets its query:
`blank` sends an empty string (all suggestions), `current` sends the input's current
text.

## Multiple

`multiple` switches the model to an **array**: each chosen suggestion displays as a
removable chip (`ui-chip`) in the field, typing resets to empty after each pick and the
panel closes. `Backspace` on empty input removes the last value; `←` from the
start of the input moves focus to the chips (navigation `←`/`→`, removal `Backspace`/
`Delete`). `unique` (default) ignores already-selected choices — equality relies on
`dataKey` for objects (without `dataKey`, two distinct instances are considered
different). In `multiple` mode, free typing never modifies the selection and `showClear`
clears the entire array. `maxSelectedLabels` limits how many chips are shown: the rest
collapses behind an informational chip whose label comes from `overflowLabel` (`{0}` = hidden
count). With `forceSelection`, unrecognized input is simply cleared on blur, without
touching the selection. The default rendering of values is a removable `ui-chip`; the
`#selectedItem` template replaces it entirely (see
[Custom Selected Item](#custom-selected-item)).

<Canvas of={AutocompleteStories.Multiple} />

## Custom Selected Item

In `multiple` mode, the `#selectedItem` template is rendered **once per selected
value** — ideal for displaying the selection as a customized
[`ui-chip`](?path=/docs/components-ui-informative-ui-chip--docs). The context
exposes `$implicit`/`option` (the original suggestion), `index` and a **`remove`** callback:
wire it to the chip's remove action (`removable` + `(remove)="remove()"`) to
remove a value **directly from the field**. When the template is provided, the values' a11y
(roles, focus) is **delegated to the consumer's template** — the component removes its
default chip listbox; on the keyboard, `Backspace` on empty input still removes
the last value. `maxSelectedLabels` and `overflowLabel` remain active: overflow
collapses behind the informational overflow chip.

```html
<ng-template #selectedItem let-country let-remove="remove">
  <ui-chip [label]="country.name" level="highlight" size="small" [removable]="true" (remove)="remove()" />
</ng-template>
```

## Force Selection

`forceSelection` validates manual input on blur: if the text matches no
suggestion, the input is cleared — the value carried in the model is **always** one of
the suggestions.

## Objects

Suggestions can be objects: `optionLabel` sets the displayed label, but the value
carried by the model remains the suggestion's **instance** (e.g. `{ name: 'France', code: 'FR' }`).
`optionValue` lets you carry only one field.

<Canvas of={AutocompleteStories.Objects} />

## Template

The component offers several customization templates: `#item` (a suggestion),
`#selectedItem` (a selected value, `multiple` mode — see
[Custom Selected Item](#custom-selected-item)), `#group`
(group header), `#header` / `#footer` (content pinned above/below the list) and
`#empty` (empty state).

## Virtual Scroll

Virtual scrolling renders a small subset of suggestions in the viewport at any
given moment — essential for very large lists. `virtualScroll` enables it and
`virtualScrollItemSize` sets a row's height.

## States

The input follows the `ui-field` shell's `form.*` states (default / hover / focus / disabled / error).
In the panel, each suggestion shares the same rendering for **visual focus**
(`aria-activedescendant`) and **hover** (`global.high.surface.hover`); the suggestion
matching the current value is highlighted (`form.high.surface.hover` +
`form.high.content.checked`). Interactive states are handled in CSS via tokens, never
by Angular props.

## Forms

The component is a `ControlValueAccessor`: it wires up with no extra code to
**Signal Forms** (`@angular/forms/signals`, `[formField]` directive, stable since Angular 22)
via native CVA interop, as well as to template-driven (`[(ngModel)]`) and reactive
(`[formControl]`) forms. In every case, the model carries the selected value (string, suggestion
object, or `optionValue` field); the `completeMethod` → `suggestions` flow stays unchanged.

<Canvas of={AutocompleteStories.SignalForms} />

The [Invalid](#invalid) example above illustrates the (reactive) `[formControl]` wiring with
`required` validation.

```html
<!-- Signal Forms -->
<ui-autocomplete [formField]="country" [suggestions]="results()" (completeMethod)="search($event)" />

<!-- Template-driven -->
<ui-autocomplete [(ngModel)]="country" [suggestions]="results()" (completeMethod)="search($event)" />

<!-- Reactive -->
<ui-autocomplete [formControl]="countryCtrl" [suggestions]="results()" (completeMethod)="search($event)" />
```
