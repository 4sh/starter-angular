# ui-field-sign

**Handwritten signature** field built on the
[`ui-field`](?path=/docs/components-ui-forms-ui-field--docs) shell (label + box + helper).
**The field box is the drawing area**: finger, stylus or mouse.

Model value = a data URL (`image/png` or `image/svg+xml`, per `format`), or `null` while
nothing is signed — so `required` works as is.

Standalone, `[(ngModel)]`, reactive forms or Signal Forms (`ControlValueAccessor` via
`BaseFormField`).

## API

<ArgTypes of={SignStories} />

```html
<ui-field-sign label="Customer signature" required [(ngModel)]="signature" />
```

## Value

The value is emitted **when each stroke ends** (the pointer is released), then on every
clear or undo — never while drawing: a form bound to an autosave would otherwise receive one
image per pointer move.

`format="png"` (default) exports an image twice as dense as the drawing frame, the same on
every device; `format="svg"` exports a vector path, lighter and sharp at any scale.

<Canvas of={SignStories.Svg} />

### Two inks: screen and export

On screen the ink follows the tokens (`--form-high-content-default`), dark theme included.
The export is painted with **`exportColor`** (`black` by default) on a **transparent
background**: a signature drawn in dark mode would otherwise come out white, unreadable on
the PDF it is meant for. A value the browser does not take as a colour falls back to `black`
— an invalid `stroke` would make the SVG export invisible.

```html
<ui-field-sign label="Signature" exportColor="#1d3b8f" [(ngModel)]="signature" />
```

### A fixed frame

The size of the box at the **first stroke** becomes the signature's frame: the strokes are
stored in it, the screen fits it into the box (scaled, centred) and the export is always that
size. A box that changes size afterwards — a phone rotated halfway through — scales the
drawing instead of cropping part of it out of the value. Clearing the field releases the
frame; the next stroke takes the box as it is then.

### Value written by the form

The field accepts an **image data URL** — what it emits itself (`png`, `jpeg`, `webp` or
`svg+xml`). Anything else, a remote URL in particular, is ignored with a warning in
development: drawn on a canvas it would make the PNG export throw, and carried into an SVG
export it would be fetched by whatever renders that file later. Convert a stored signature
to a data URL before handing it to the field.

The value is shown in the box and stays **under** new strokes until cleared. On screen it is
redrawn as a silhouette in the current ink, so that a black signature stays legible on a dark
field; it is fitted to the frame, keeping its proportions. An image that cannot be loaded
leaves the field empty rather than announced as signed over a blank box. In PNG, a stroke
drawn before the previous signature has loaded is held until it has: the export never drops
it.

## Clear, undo

- The clear button (`clearable`, enabled once the area is signed) empties the field and hands
  focus back to the drawing area.
- `clear()` and `undo()` are public, for a "Start again" or "Undo" button owned by the host.
  `undo()` removes the last stroke drawn in the field, and with none left brings back what the
  last `clear()` removed. A signature received from the form is not a stroke: only `clear()`
  removes it.
- On the keyboard, on the drawing area: `Backspace` or `Ctrl`+`Z` (`⌘`+`Z`) undo the last
  stroke, `Delete` clears — undoable too.

```html
<ui-field-sign #sign label="Signature" [clearable]="false" [(ngModel)]="signature" />
<ui-button label="Undo last stroke" level="low" (buttonClick)="sign.undo()" />
```

## Drawing

- Strokes are **smoothed** (quadratic curves between segment midpoints) and follow the device
  at its own rate (`getCoalescedEvents`), not the screen's.
- `touch-action: none` on the area: **the page does not scroll** under the finger while
  signing, and the pointer is captured until released, even when it leaves the box. A lost
  capture ends the stroke like a release.
- A second finger put down during a stroke is ignored, and so is any button but the main one
  (right-click, stylus eraser).
- The area is redrawn on every resize, at the screen's density.

## Levels & states

`level` (`default`/`success`/`error`) drives the border, `errorText` replaces the helper in
error — the same contract as every field built on `ui-field`. In `readonly` the signature
stays visible but can no longer change, and the clear button goes away.

stand in for.

## Forms

The field is a `ControlValueAccessor`: `required` / `Validators.required` reject `null`,
`disable()` from the form stops the pen, `reset()` empties the box. A form writing back the
value it just received (`control.setValue(control.value)`, a `patchValue` of the whole form)
keeps the strokes — and their undo history — as they are.

## Accessibility

- A handwritten signature is a **path-based** gesture: WCAG exempts it from keyboard
  alternatives (2.1.1, path-dependent exception) and from simplified gestures (2.5.1,
  essential gesture). The area is still a **tab stop**, so that clearing and undoing can be
  reached from the keyboard.
- The area is exposed as an image (`role="img"`), named by the `label` (or `ariaLabel`),
  described by its state — the hint while empty, `signedLabel` once signed, followed by
  `requiredLabel` when the field is `required` — then by the helper or error message.
- The clear button carries `clearAriaLabel`.
- Focus is visible on the box (the shell's `:focus-within` ring), from the pointer as from the
  keyboard.

## Theming

The box, label, helper and clear button come from the `ui-field` shell (`utils.field-*`
mixins), configured by the shared
[Forms](?path=/docs/components-configuration-forms--docs) group. The ink is set here: its
screen colour and its width, read by the canvas on every paint. See also
[how configuration works](?path=/docs/components-configuration--docs).
