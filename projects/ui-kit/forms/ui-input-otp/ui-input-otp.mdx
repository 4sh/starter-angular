# ui-input-otp

**One-time password** (OTP) field

<Canvas of={InputOtpStories.Basic} />

## Basic

An OTP split into single-character cells. `length` sets the number of cells (4 by default).

```html
<ui-input-otp [length]="4" ariaLabel="Verification code" />
```

## Controlled

Component controlled via `[(ngModel)]`: the joined value is available on the parent side.

<Canvas of={InputOtpStories.Controlled} />

```html
<ui-input-otp [(ngModel)]="code" ariaLabel="Verification code" />
```

## Mask

`mask` masks the entered characters (rendered as `type="password"`).

<Canvas of={InputOtpStories.Mask} />

```html
<ui-input-otp [(ngModel)]="code" [mask]="true" ariaLabel="Secret code" />
```

## Integer Only

`integerOnly` restricts input to digits (`inputmode="numeric"` → numeric keyboard on
mobile). Non-numeric characters are rejected, both when typing and pasting.

<Canvas of={InputOtpStories.IntegerOnly} />

```html
<ui-input-otp [(ngModel)]="code" [integerOnly]="true" [length]="6" ariaLabel="Numeric code" />
```

## Sizes

Three sizes: `small`, `default` (base) and `large`.

<Canvas of={InputOtpStories.Sizes} />

```html
<ui-input-otp size="small" ariaLabel="Code" />
<ui-input-otp size="large" ariaLabel="Code" />
```

## Disabled

With `disabled`, the component becomes non-interactive (native attribute on each cell).

<Canvas of={InputOtpStories.Disabled} />

```html
<ui-input-otp [(ngModel)]="code" [disabled]="true" ariaLabel="Verification code" />
```

## Template

The `#input` template **replaces the default cell** with your own UI. It receives the context
`value` (`$implicit`), `index`, `tabindex` (the roving value to apply to your `<input>`) and `events` —
the handlers to wire up (`input`/`keydown`/`focus`/`blur`/`paste`) to keep the full
mechanics working (keyboard navigation, auto-advance, spread paste).

<Canvas of={InputOtpStories.Template} />

```html
<ui-input-otp [(ngModel)]="code" [integerOnly]="true" [length]="4" ariaLabel="Code">
  <ng-template #input let-value let-i="index" let-events="events" let-tabindex="tabindex">
    <input
      [value]="value"
      [attr.tabindex]="tabindex"
      maxlength="1"
      (input)="events.input($event)"
      (keydown)="events.keydown($event)"
      (focus)="events.focus($event)"
      (blur)="events.blur($event)"
      (paste)="events.paste($event)"
    />
  </ng-template>
</ui-input-otp>
```

## States

- **Base** — border `form.high.stroke.default`, surface `form.high.surface.default`.
- **Hover** — `form.high.stroke.hover`.
- **Focus** — `form.high.stroke.focused` + focus ring (`:focus-visible`, distinct from hover).
- **Invalid** — `form.error.*` palette (via `invalid`, or automatically when the attached control
  is invalid **and** touched/dirty).
- **Disabled / Read-only** — native attributes; colors via `form.high.*-disabled` tokens.

- Each cell is a native `<input>` (screen reader support inherited from the text field), named
  "`ariaLabel` + cell number".
- The group **requires** an accessible name: set `ariaLabel` (or `ariaLabelledBy`) — a
  dev-mode warning is emitted otherwise.
- `:focus-visible` stays distinct from `:hover`; the `disabled` state is native (not just visual).

## Forms

`ui-input-otp` is a `ControlValueAccessor`: it wires up with no extra code to
**Signal Forms** (`@angular/forms/signals`, `[formField]` directive, stable since Angular 22)
via native CVA interop, as well as `[(ngModel)]` and **Reactive Forms**
(`[formControl]`/`[formControlName]`) — the interop is handled by `BaseControlValueAccessor`
(a control with no `events` stream). The model's value is the cells' **joined string**.

<Canvas of={InputOtpStories.SignalForms} />

```html
<!-- Signal Forms -->
<ui-input-otp [formField]="field" ariaLabel="Code" />

<!-- Template-driven -->
<ui-input-otp [(ngModel)]="code" ariaLabel="Code" />

<!-- Reactive -->
<ui-input-otp [formControl]="codeCtrl" ariaLabel="Code" />
```

## Theming

Cell dimensions are driven by a local `$sizes` map; structural constants
(radius, border thickness, focus ring) are **reused** from the shared
`ui-config` configuration (see [Configuration](?path=/docs/design-system-configuration--docs)
and the [Forms](?path=/docs/design-system-configuration-forms--docs) page).
