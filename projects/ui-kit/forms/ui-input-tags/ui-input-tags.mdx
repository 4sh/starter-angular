# ui-input-tags

**Multi-value** input field built on the shared
[`ui-field`](?path=/docs/components-ui-forms-ui-field--docs) shell (label + box + helper). The box
hosts a list of **tags** (removable chips) and an inline input: type a value and
`Enter` adds it, `Backspace` (empty field) removes the last one.

<Canvas of={InputTagsStories.Basic} />

## Basic

`Enter` adds the typed value; `Backspace` (empty input) removes the last tag. On the
keyboard, `←`/`→` move focus between tags, `Delete`/`Backspace` on a focused tag
removes it.

```html
<ui-input-tags label="Technologies" [(ngModel)]="keywords" placeholder="Add…" />
```

## Delimiter

A `delimiter` (e.g. a comma) adds tags in addition to `Enter`. With `addOnPaste`, pasted
text is split on the delimiter (or, failing that, on spaces/newlines/`,`/`;`).

<Canvas of={InputTagsStories.Delimiter} />

## Allow Duplicate

By default, a value already present isn't re-added. `allowDuplicate` allows duplicates.

<Canvas of={InputTagsStories.AllowDuplicate} />

## Max

`max` caps the number of tags: once the limit is reached, input is blocked until
a tag is removed.

<Canvas of={InputTagsStories.Max} />

## Template

By default, each tag is rendered with a removable
[`ui-chip`](?path=/docs/components-ui-informative-ui-chip--docs) — consistent with the
rest of the design system. Its color is set via `chipLevel` / `chipSubLevel` (see _Styled_).

For a **fully custom** rendering (icon, avatar, business color…), provide an
`#item` template: it replaces the default `ui-chip`. The context exposes `value`, `label`,
`index` and an `onRemove` callback to wire to the remove action.

<Canvas of={InputTagsStories.Template} />

## Styled

The default `ui-chip` tags take color via `chipLevel` (family) and `chipSubLevel`
(`low`/`high` intensity), with no need for a template.

<Canvas of={InputTagsStories.Styled} />

## Typeahead

With `typeahead`, a suggestion list displays in an overlay while typing (a
debounced `completeMethod` request, `delay`, `minLength` threshold). The parent sets `suggestions`.
Already-added values are marked (checked) and not re-selectable (unless `allowDuplicate`).

<Canvas of={InputTagsStories.Typeahead} />

## Forms (ngModel / Reactive / Signal Forms)

`ui-input-tags` is a standard `ControlValueAccessor`: its value is a `string[]` (or `T[]`).
It wires up with no extra code to **Signal Forms** (`@angular/forms/signals`,
`[formField]` directive, stable since Angular 22) via native CVA interop, and works identically
with template-driven (`[(ngModel)]`) and reactive (`[formControl]`) forms.

<Canvas of={InputTagsStories.SignalForms} />

```html
<!-- Signal Forms -->
<ui-input-tags label="Tags" [formField]="tags" />

<!-- Template-driven -->
<ui-input-tags label="Tags" [(ngModel)]="tags" />

<!-- Reactive Forms -->
<ui-input-tags label="Tags" [formControl]="tagsCtrl" />
```

Validation state (`touched`/`dirty`/`invalid`) is reflected in internal signals
(`BaseControlValueAccessor`), including via the Signal Forms interop (a control with no `events`
stream). The error style therefore activates automatically when the control is invalid **and** touched/dirty.

## States

The whole thing follows the `ui-field` shell's `form.*` states (default / hover / focus / disabled / error).
Each tag is a `ui-chip` (`informative.*` tokens, `chipLevel`/`chipSubLevel`); the option
wrapper carries roving focus (`:focus-visible` → `form.high.stroke.focused` ring). In the suggestions panel,
visual focus and hover share `global.high.surface.hover`; an already-added suggestion is
marked `form.high.content.checked`. Interactive states are handled in CSS via tokens.
