## Basic

The panel is accessed via its reference: the trigger's click event carries
the anchor, and visibility is driven by `toggle` / `show` / `hide`.

```html
<ui-button label="Details" (buttonClick)="op.toggle($event)" />
<ui-popover #op ariaLabel="Product details">
  <p>Panel content…</p>
</ui-popover>
```

## Controlled

Visibility can be driven from the outside via the reference variable. **Pass
the triggering element as the second argument** so the overlay stays anchored
to it, regardless of which button drives the state.

```html
<span #anchor>Anchor</span>
<ui-button label="Show" (buttonClick)="op.show($event, anchor)" />
<ui-button label="Hide" (buttonClick)="op.hide()" />
<ui-button label="Toggle" (buttonClick)="op.toggle($event, anchor)" />
<ui-popover #op ariaLabel="Controlled panel"><p>…</p></ui-popover>
```

## Positions

`position` picks the preferred side (`top` / `bottom` / `left` / `right`); the overlay
automatically flips to another side if there's not enough room, and the arrow orients
according to the effective side.

<Canvas of={PopoverStories.Positions} />

## Rich content

Projected content is free-form and can be interactive. A dedicated close button
simply calls `hide()` — its keyboard activation (`Enter` / `Space`) is the
native behavior of a `<button>`.

## Accessibility

<table className="doc-table">
  <thead>
    <tr>
      <th>Rule</th>
      <th>Detail</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><strong>Role & name</strong></td>
      <td><code>role="dialog"</code>, non-modal by default (WAI-ARIA "non-modal dialog" pattern): no <code>aria-modal</code>, focus can leave the panel (via keyboard, or an outside click). Name it via <code>ariaLabel</code> or <code>ariaLabelledBy</code>; a dev warning flags an open panel with no accessible name.</td>
    </tr>
    <tr>
      <td><strong>Trigger relationship</strong></td>
      <td>On open, the trigger receives <code>aria-expanded="true"</code> and <code>aria-controls</code> (panel id); cleaned up on close. Use a keyboard-accessible trigger (<code>&lt;button&gt;</code>), otherwise add <code>tabindex</code>.</td>
    </tr>
    <tr>
      <td><strong>Focus</strong></td>
      <td>By default focus is not trapped: <code>Tab</code> / <code>Shift+Tab</code> can leave the panel once the last / first focusable element is reached. Enable <code>modal</code> for a blocking dialog behavior: <code>aria-modal="true"</code> and a permanent focus trap (<code>cdkTrapFocus</code>) while the panel is open. In every case, on open (<code>focusOnShow</code>), the **first focusable element** receives focus — customizable by adding the <code>autofocus</code> attribute on an element in the panel.</td>
    </tr>
    <tr>
      <td><strong>Keyboard</strong></td>
      <td><code>Tab</code> / <code>Shift+Tab</code> cycle within the panel. <code>Escape</code> closes (<code>closeOnEscape</code>) and returns focus to the trigger.</td>
    </tr>
    <tr>
      <td><strong>Outside click</strong></td>
      <td><code>dismissable</code> (default) closes on a click outside the panel; a click on the trigger is ignored (its own handler toggles the state).</td>
    </tr>
    <tr>
      <td><strong>Motion</strong></td>
      <td><code>zoom</code> entrance via the motion system; respects <code>prefers-reduced-motion</code> and the global <code>data-motion="off"</code> switch, can be disabled per instance via <code>motion="false"</code>.</td>
    </tr>
  </tbody>
</table>

thickness, shadow) comes from the shared `$overlay-panel-*` constants in `ui-config` — see
