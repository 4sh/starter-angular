# ui-image

Smart image component with two sources: `name` (local asset resolved via the assets-map based on
the active brand `BrandService` and the light/dark mode `ThemeService`) or `src` (remote/absolute
URL, takes priority over `name`). Based on `NgOptimizedImage` for loading performance.

**Local** `.svg`s are injected inline (CSS styling possible, fetched via `httpResource` + shared
cache); a **remote** `.svg` always goes through `<img>` (never inlined — no XSS surface). On load
failure, the `fallback` local asset takes over, then a token-styled placeholder (light/dark
adapted) if the fallback also fails or isn't provided; the `loadFailed` output emits the failing URL.

## Usage rules (DOs & DON'Ts)

<table className="doc-table">
  <thead>
    <tr>
      <th>DO</th>
      <th>DON'T</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>
        Always provide the <code>name</code> attribute with the full filename (extension included):
        <pre><code>{`<ui-image
  name="logo.svg"
  [width]="200"
  widthUnit="px"
  alt="Application logo">
</ui-image>`}</code></pre>
      </td>
      <td>
        Don't provide a full path in <code>name</code> — the component builds the path itself via the assets-map:
        <pre><code>{`<!-- WRONG -->
<ui-image name="assets/img/common/base/logo.svg">
</ui-image>`}</code></pre>
      </td>
    </tr>
    <tr>
      <td>
        Use <code>src</code> for a remote URL, with <code>width</code> + <code>height</code> (or <code>fill</code>) — required by NgOptimizedImage:
        <pre><code>{`<ui-image
  src="https://cdn.example.com/photo.jpg"
  [width]="400"
  [height]="300"
  alt="Remote photo">
</ui-image>`}</code></pre>
      </td>
      <td>
        Don't provide both <code>src</code> AND <code>name</code> (precedence to <code>src</code>, warning in dev); don't use a <code>data:</code>/<code>blob:</code> URL (unsupported by NgOptimizedImage):
        <pre><code>{`<!-- WRONG -->
<ui-image
  src="data:image/png;base64,…"
  name="logo.svg">
</ui-image>`}</code></pre>
      </td>
    </tr>
    <tr>
      <td>
        Provide a <code>fallback</code> (a <strong>local</strong> assets-map asset name) for uncertain sources — rendered via <code>&lt;img&gt;</code> even for a <code>.svg</code>:
        <pre><code>{`<ui-image
  src="https://cdn.example.com/avatar.jpg"
  fallback="avatar-default.png"
  [width]="48" [height]="48"
  alt="Avatar">
</ui-image>`}</code></pre>
      </td>
      <td>
        Don't pass a URL as <code>fallback</code> — it's a local assets-map key, not a remote source:
        <pre><code>{`<!-- WRONG -->
<ui-image
  src="https://cdn.example.com/a.jpg"
  fallback="https://cdn.example.com/b.jpg">
</ui-image>`}</code></pre>
      </td>
    </tr>
    <tr>
      <td>
        Use <code>[fill]="true"</code> with a <code>position: relative</code> parent container for fill-mode images:
        <pre><code>{`<!-- Parent container -->
<div style="width: 400px; height: 300px; position: relative;">
  <ui-image name="hero.jpg" [fill]="true" alt="Hero"></ui-image>
</div>`}</code></pre>
      </td>
      <td>
        Don't use <code>[fill]="true"</code> together with <code>[width]</code> or <code>[height]</code> — these properties are mutually exclusive with <code>fill</code>:
        <pre><code>{`<!-- WRONG -->
<ui-image
  name="hero.jpg"
  [fill]="true"
  [width]="400">
</ui-image>`}</code></pre>
      </td>
    </tr>
  </tbody>
</table>

`--global-background-muted`/`--global-text-muted`/`--units-xl`/`--radius-default` tokens. See
[how the configuration works](?path=/docs/components-configuration--docs).
